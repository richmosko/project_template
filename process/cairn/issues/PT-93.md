## Problem

Measured 2026-09-05 at the PT-85 loop (user's question: "how many tests get run every time?"):

| Suite | Tests | Files | Wall time |
|---|---|---|---|
| Python (`unittest discover`, serial) | 1327 | 77 | ~155 s |
| JavaScript (`node --test`) | 458 | 47 | <1 s |

Every teammate runs the full Python suite repeatedly inside a loop (qa after each commit,
implementation-lead before each report, the architect on a clean control, the lead at
pre-flight) — 15–20 full runs per feature, each blocking that agent for 2.5 min. Per-file wall
time (top of 77): test_server 22.4 s, test_otel_receiver_self_stop 19.0, test_dashboard 13.5,
test_backfill_tokens 12.9, test_show_archived 12.2, test_record_mutation 9.5, test_root_redirect
8.0, test_cli 6.3, test_otel_receiver 6.1, test_otel_receiver_hardening 5.1. The top seven files
are ~97 s of the 155: they spawn real servers/daemons (with grace-window waits) or build a fresh
git repo per test. 30 of 77 files use subprocess or temp-dir repos.

## Ask (in payoff order)

1. **Tiered gating** (WORKFLOW → Implement inner loop): during a loop a teammate runs the modules
   touched plus the guard modules (`discover -p "test_<area>*.py"`); the full suite runs at two
   points only — qa's final pass and the /finish-feature gate. Write the rule and the command.
2. **Parallel runner**: a small script (`scripts/cairn/run_tests.py`) that runs the 77 files
   across N workers (files are independent; unittest has no parallelism) and aggregates
   pass/fail/skip counts and exit code; wire /finish-feature's gate and the WORKFLOW commands to
   it. Target: ≤45 s on 4 workers, same counts.
3. **Fixture reuse**: in the top seven files, build the git fixture repo / spawn the daemon once
   per module (`setUpModule`) where tests only read it; per-test construction stays only where a
   test mutates the fixture. Re-measure per file.
4. **Consolidation**: merge per-feature sliver files (2–5 tests on one subject) by subject;
   retire tests whose subjects were retired (PT-85's ramp guard is one). Same count discipline
   as PT-87: delete no test whose rule is still true; record each retirement on this issue.

## Acceptance criteria

1. Full Python suite wall time ≤ 45 s via the runner on this machine, identical pass/skip counts
   to serial; serial `unittest discover` still works and agrees.
2. WORKFLOW and /finish-feature name the tiered rule and the runner command.
3. Per-file timing recorded before/after for the top seven files.
4. No test deleted without a comment on this issue naming the retired rule; `cairn check` ok;
   real data file and registry untouched.
