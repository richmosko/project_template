rendering real repo state, plus `docs/DESIGN/tokens.css` (the `:root`/`.dark`
blocks from the design-system spec, verbatim) consumed by the new page.

**Acceptance criteria**
- [ ] `docs/DESIGN/tokens.css` exists with the preset's light + dark token
      blocks exactly as specified in `design-system-spec.md`
- [ ] `GET /dashboard` serves a page styled per the spec's Dashboard scale
      (fonts decision — self-host vs Google Fonts — needs an architect ruling
      first; board.css's standing principle is no CDN)
- [ ] Status cards render real data: current branch + clean/dirty (git),
      latest tag + release row (git tag / STATE.md), tracker counts by status
      (engine), `cairn check` result
- [ ] Data comes from the server (engine + subprocess git), never shelling
      out client-side; refresh piggybacks the existing SSE/poll channel
- [ ] Tests cover the new endpoint's payload (JS/py harness per repo norms)
