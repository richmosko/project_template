## Problem

`GET /api/board` intermittently returns 503 — observed twice (2026-08-22): during PT-29's Chrome pass at page load (two 503s racing the SSE connection setup), and during PT-32's Validate on a pull-triggered refetch while the SSE stream was open. Suspected: the single-threaded board server can't serve a fetch while an SSE (`/api/events`) long-lived connection is being established/held. Split out of PT-31 item 4 (architect, PT-32 Validate): it's a server-side defect and doesn't belong in a client-polish bundle — the client-side symptom hardening (PT-32's three-state refresh outcome + `apiGetBoard` resp.ok guard) already shipped and makes the failure honest, not absent.

## Acceptance criteria

- [ ] Race reproduced deliberately (concurrent /api/board fetch during /api/events connection churn) or ruled out with the actual 503 source identified
- [ ] Fix lands server-side (threading/handler model in `cairn serve`) — client behavior unchanged
- [ ] Regression test or documented manual repro in the Python suite
