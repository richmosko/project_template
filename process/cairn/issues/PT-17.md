## Comments

### @team-lead — 2026-08-20

Root cause of the two-session "SendMessage outage" (SC1 2026-08-19, SC2 2026-08-20),
found by Mosko's question: every agent definition carries an explicit `tools:`
allowlist and none includes SendMessage, so spawned teammates are never granted it —
`Error: No such tool available: SendMessage`. The outage is deterministic, not a
harness fault. Asymmetry explained: the lead's SendMessage TO teammates works (lead
isn't governed by agents/*.md); only the teammate back-channel is missing, which the
temp/-file protocol has been compensating for.

Fix: add `SendMessage` to the tools frontmatter of all 10 files under
.claude/agents/ (9 specialists + mcp-broker). Acceptance: spawn a teammate, have it
SendMessage the lead, message arrives; WORKFLOW.md's coordination language and the
teammate-outage guidance in agent briefs/skills reviewed for now-stale caveats
(keep temp/ as documented fallback — it's proven).

Capability-grant note: this widens what teammates can do (message the lead, each
other, and cross-session targets). Ruled in scope of the template's own coordination
design (WORKFLOW.md assumes it); ratification of the grant is Mosko's, recorded by
pulling this into a milestone.

### @team-lead — 2026-08-20

Scope update after claude-code-guide research (docs v2.1.224+, agent-teams.md +
tools-reference.md):

1. Full coordination toolset = SendMessage, TaskCreate, TaskGet, TaskList,
   TaskUpdate (+ ListAgents, cross-session-gated). Add all of these explicitly to
   the 10 agent allowlists, not just SendMessage.
2. CAVEAT on the root-cause claim: current docs state Claude Code AUTO-ADDS
   SendMessage + the Task tools to teammate allowlists, so on a current version the
   omission alone should not produce the observed "No such tool available" /
   "disabled for this session" error. The explicit listing is documented as
   redundant-but-harmless — do it for self-documentation and robustness — but the
   acceptance test (live teammate→lead round-trip) is the real gate. If it still
   fails after the grant, the residual cause is session-level (version or
   cross-session-messaging config) and becomes a follow-up investigation, not a
   silent pass.
3. Sibling fix, same PR: mcp-broker's allowlist (Read, Grep, Glob, Write, Edit)
   cannot reach any MCP tool — its entire purpose. Add ToolSearch (tool search is
   enabled in this environment) or direct mcp__* patterns for Drive/Gmail/Calendar.
