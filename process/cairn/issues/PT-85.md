## Problem

The PT-61 "Issue flow over time" chart plots the count of issues in each status per day,
including archived issues while they were live. Its meaning is inconsistent across series: `done`
only ever grows (closed issues never leave it), while `backlog`, `todo`, `in-progress` and
`in-review` drain as issues move on. So the top of the stack reads as "79 done" on a day when four
issues closed, and nothing on the chart says how much work moved that day. The user read it as a
count of today's work and it is not; the caption that explains it is small print.

## Ruling (team-lead with the user, 2026-09-04)

Replace the status-stack with a **throughput view**. Cumulative status counts are not a
consistent measure; flow is.

1. Primary chart: per period (day by default, week toggle), bars for **issues closed** (done) and
   **issues opened** (created), on the same axis, so a day reads "4 closed, 4 opened".
2. A **WIP line** on the same chart: issues in `in-progress` + `in-review` at the end of each
   period. Point-in-time, and labelled as such.
3. **Milestone scope**: a control to scope the chart to one milestone (default: the milestone
   with the most recent activity) or all. Archived milestones selectable.
4. The status-stack area chart is removed from the default view; if kept at all, it is behind a
   toggle and its caption states "cumulative counts, not activity" in the first sentence.
5. Same data source as today (`/api/flow`, git-reconstructed daily states); the server computes
   opened/closed deltas per period so the client stays pure. `cancelled` counts as neither
   opened nor closed for throughput; shown in the tooltip only.

## Acceptance criteria

1. `/api/flow` (or a sibling endpoint, architect's call) returns per-period opened, closed, WIP,
   and cancelled, per milestone and overall; memoized like the current payload.
2. The dashboard block renders bars + WIP line with the day/week and milestone controls; caption
   names the period, the scope, and that WIP is end-of-period.
3. Drawer unaffected. Sidebar status cards unaffected.
4. Tests at the Python endpoint level (fixture history with opens, closes, cancels, a milestone
   boundary) and structural tests for the block; browser-visibility leg per the standing protocol.
5. `process/TRACKER.md` and the dashboard section of the design-system spec updated; PT-61's
   ordinal `--chart-flow-*` tokens either reused for the two bar series and the line or retired
   with the token guard adjusted.
