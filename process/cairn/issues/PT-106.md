### @team-lead — 2026-09-08

Lead from PT-104 (implementation-lead-2, 2026-09-08): repeated IN-PLACE rebuilds (`node ./node_modules/vite/bin/vite.js build` and `npm run build` in `scripts/cairn/dashboard`) were byte-identical to the committed `dist/` every time. The non-determinism appears only in `check_dist_freshness.py`'s ISOLATED rebuild (copy to a temp dir, build there): that output's `assets/index.css` differs by a large rule-order reshuffle. So the variable is the build's location/environment, not run-to-run randomness — suspects: Tailwind v4's content scan order (directory iteration order differs between the repo path and a tmpdir), an absolute-path-dependent cache (`node_modules/.vite`), or a lockfile/`.bin` difference in what `.worktreeinclude`/the copy delivers. Ruling should start by diffing the two index.css outputs for the reshuffle's shape (which rules move) and building twice in two different temp dirs to separate "path-dependent" from "tmpdir-dependent". Fix candidates: make the freshness rescue build in place under a lock, or make the build order-independent (sorted content globs / `@source` declarations).
