### @architect — 2026-09-08

**Ruling (gate 1).** Six builds, `node ./node_modules/vite/bin/vite.js build`, sha256 of every `dist/assets/*` plus `index.html`. **Only `assets/index.css` ever differs** — all 65 other files are byte-identical in all six.

| build | where | previous `dist/` present at build time? | `index.css` |
|---|---|---|---|
| committed HEAD | — | — | `be226fc41df6` |
| A1, A2 | in place, consecutive | yes | `e84ee3e64bdd` (both) |
| B1, B2 | two different tmpdirs (the freshness checker's own recipe) | no — its copy removes `dist` | `be226fc41df6` (both) |
| **C** | **in place, `dist` removed first** | **no** | **`be226fc41df6`** |
| **D** | **isolated tmpdir, `dist` left in the copy** | **yes** | **`e84ee3e64bdd`** |

**The variable is neither the path nor run-to-run randomness: it is whether a previous `dist/` exists when the build runs.** C and D cross the two factors and separate them cleanly — in place without dist gives the isolated result; isolated with dist gives the in-place result. The build is a deterministic function of (sources, presence of prior output). A1==A2 and B1==B2 both hold, so there is no randomness to chase.

**Both prior readings resolve.** PT-104 saw the isolated rebuild "reshuffle" because the *committed* dist was then the dist-present shape while the checker always builds clean — the checker was right and the artifact was the odd one out. PT-82's "two consecutive `rm -rf dist && npm run build` runs differ" does **not** reproduce: four clean builds here agree byte-for-byte. Treat it as superseded by measurement; do not design for it.

**Cause, end to end.** Root `.gitignore:35` ignores `dist/`, then `:45` negates it (`!scripts/cairn/dashboard/dist/`) so this app's build output can be committed. Tailwind v4's automatic source detection scans the project tree *respecting .gitignore* — the negation therefore makes the previous build's own emitted JS/CSS a content source, and the class-name strings in it feed the next build's utility emission. The build output is an input to the next build.

**Fix: `@source not "../dist";` in `src/app.css`, immediately after the leading `@import` block** (Tailwind v4 requires the imports to lead; the path is relative to the CSS file). Measured on copies, never in the repo — patched + dist present → `be226fc41df6`; patched + dist absent → `be226fc41df6`. Both equal the committed artifact byte-for-byte, which is also the check that the narrowed scan drops no utility. Installed Tailwind is 4.3.3, so `@source not` is available.

**Rejected: making the freshness rescue build in place under a lock.** It would make the checker agree with whatever state the tree happens to be in and leave the build a function of its own previous output — the defect, papered over at the one place that currently detects it. **Also rejected: `rm -rf dist` as a build-script step** — the artifact would then depend on a preceding step rather than on the sources, and any consumer building without it still gets different CSS.

**Guard (qa) — one build, not two.** Copy the dashboard to a tmpdir **with its `dist/` left in place**, build, and assert every `dist/assets/*` and `index.html` is byte-identical to the committed `dist/`. That is exactly the property (build ⊥ previous output), and equality against the committed artifact simultaneously pins "no utility lost". Skip with a named reason when `node_modules` is absent. Do **not** add a second build for the two-tmpdir case: measured above, B1==B2 and A1==A2 already hold today, so it would cost ~10 s per suite run to re-assert something that was never broken.

**No dist rebuild in this loop.** HEAD's `dist/` is already the clean shape and the fix reproduces it byte-for-byte (C, and both patched builds), so the fix commit changes no artifact. `check_dist_freshness.py` is unchanged.

**Scope** — `src/app.css` (one line) and the new test. Writers: implementation-lead → `app.css`; qa → the test.

**What this loop actually bought.** The rescue in `check_dist_freshness.py` has existed since PT-82 and, on this dashboard, could never fire: the checker built clean while the committed artifact carried the dist-present shape, so every honest dist commit looked stale and every rebuild produced noise. With the feedback loop cut, the same rescue now reports what it was written to report. The gate did not change; the thing it measures became measurable.

**One durable note for whoever revisits `.gitignore`.** The negation at `:45` (`!scripts/cairn/dashboard/dist/`) is load-bearing for two different systems: git needs it to commit the artifact, and Tailwind reads the same file to decide what to scan. Those two readers have opposite interests, and `@source not "../dist"` is what keeps them apart. If the ignore rules are ever restructured, that line is the one to re-check first — it is the only thing standing between the build and its own output.

**No residuals.** Everything the ruling asked for landed, and nothing beyond it did.
