**Item 5 is not drift**, and the issue text assumes all five are. It matters: a gate that cannot pass is not a gate, so if `svelte-check` joins the finish pre-flight, line 552 must be fixed in this loop too. It is in scope.

**(1) Owner: `dashboard-api.ts`.** It is the wire boundary — `fetchTokens()` is where the payload is parsed, and a type that describes a wire response belongs with the code that receives it. `token-chart-logic.ts` deletes its copies and imports (`import type { … } from './dashboard-api'`); direction is logic → api, and `dashboard-api.ts` imports nothing from the chart module, so no cycle. **No re-export** from `token-chart-logic` — a re-export gives one type two import paths, which is how this drift started. Move `TokenKind` too (it is part of the wire shape), and carry the PT-84 §7 / PT-102 provenance comments across with their fields; they explain the fields, not the module.

**Exact shape, reconciled against `build_tokens_payload` (cairn.py ~L3645 and ~L3720), which is the source of truth:**
- `TokensPayload`: `issues`, `window_start`, `window_end`, `generated`, `sources: string[]`, `prices: { retrieved; source; unpriced_models: string[] }`, `warning: string | null`, `milestone_caption: string | null`. The "no token data" early return emits the same key set, so nothing is optional.
- `TokenIssueTotal`: `issue: string`, `kind: TokenKind`, `total: TokenCounters`, `roles: Array<TokenCounters & { role: string }>`, and **`closed_at: string | null` — required, drop the `?`**. The emitter writes the key unconditionally (`closed_at_by_issue.get(issue)`, `None` when absent), and nothing client-side constructs one of these (grepped: reads only; the JS fixtures under `tests/js/` are not typechecked). An optional key here says "may be absent", which the server never does.
- `TokenCounters` unchanged; the two copies already agree.

**(2) `svelte-check` joins the finish gate**, as step 2b of `.claude/skills/finish-feature/SKILL.md` — after the JS suite, before the dist-freshness gate. 2.44 s against a defect that survived three loops (PT-88, PT-101, PT-102) is not a close call. Guard it with `[ -d scripts/cairn/dashboard/node_modules ]` and, when absent, print a NOTE naming the reason exactly as the JS-suite branch already does — a missing local install must not block a merge, but it must say so out loud. A scan test pins the line, per PT-83.

**Line 552, constrained:** no `@ts-nocheck` on the file and no `any` on the payload. If LayerChart's own types genuinely do not admit the intended usage, one narrowly-scoped `@ts-expect-error` with a one-line reason naming the upstream type is acceptable — `@ts-expect-error`, never `@ts-ignore`, so it fails loudly when upstream fixes it.

**(3) dist:** a type-only change still trips `check_dist_freshness` (git-aware), so rebuild and commit `dist/` in the same commit. PT-106 (non-deterministic build) is out of scope; if the rebuild produces churn beyond this change, that is PT-106's problem, not a reason to skip the rebuild.

**Guards (qa):** (a) `svelte-check` exits 0 on the dashboard, skipped with a named reason when `node_modules` is absent — assert the exit code, not the text of the output; (b) the SKILL scan pins both the command and the skip-note branch (mutation: delete the line → red). Suite cost ≈ 2.4 s, parallel, well under the 20 s critical-path file.

The Snippet conversion works: values arrive and format per mode. 

**Delta 1 (visual, the fix's own side effect):** the rows carry NO series name and NO colour indicator — bare numbers. Cause, read from `ui/chart/chart-tooltip.svelte:133-141`: when `formatter` is supplied the tooltip renders `{@render formatter({value, name, item, index, payload})}` INSTEAD of its default indicator + name + value row, so the snippet is responsible for the whole row. The new snippet renders only the formatted value. A reader hovering a stacked bar sees four or five numbers with no way to tell Input from Cache read except by inferring from stack order. Fix: the snippet renders the indicator (`item.color`/the series colour), `name`, and the formatted `value` in the same layout the default branch uses (L142-165 of chart-tooltip.svelte), or — smaller — keep the default row and format via the tooltip's `labelFormatter`/value-formatting hook if the component exposes one. What main did is not the baseline: the callback-typed `formatter` was truthy there too, so `{@render}` of a plain function produced an empty row; both versions lose the names — this loop is where it gets fixed, because svelte-check is now the gate that would have caught it.

No other visual change: bar geometry, legend (Input / Cache write / Cache read / Output), mode/order toggles, caption unchanged.
