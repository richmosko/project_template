## Problem

`RealDataFileUntouchedGuard` in `scripts/cairn/tests/test_otel_receiver_self_stop.py` is a
`TestCase` with `setUpClass`/`tearDownClass`. unittest loads classes alphabetically, so the guard
brackets only its own class's tests; classes sorting after it (S/T/U-prefixed) run outside the
guard and could touch the real `token-usage.jsonl` undetected. Found by qa-engineer during PT-84
(comment on PT-84); not observed to have fired, but the mechanism is fragile.

## Ask

Convert to module-level `setUpModule`/`tearDownModule`, snapshotting the real data file AND the
runtime state beside it (`.receiver.pid`, `.sessions/`) before the first test and asserting them
byte-identical after the last — the pattern already used in `test_milestone_overhead.py` (abb41fb).

## Acceptance criteria

1. The guard covers every class in the module regardless of name order (prove it with a
   deliberately-named last class that would have escaped the old guard).
2. Full suite green; `cairn check` ok; real data file and registry untouched.
