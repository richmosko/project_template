## Problem

`RealDataFileUntouchedGuard` in `scripts/cairn/tests/test_otel_receiver_self_stop.py` is a
`TestCase` with `setUpClass`/`tearDownClass`. unittest loads classes alphabetically, so the guard
brackets only its own class's tests; classes sorting after it (S/T/U-prefixed) run outside the
guard and could touch the real `token-usage.jsonl` undetected. Found by qa-engineer during PT-84
(comment on PT-84); not observed to have fired, but the mechanism is fragile.

## Ask

Convert to module-level `setUpModule`/`tearDownModule`, snapshotting the real data file AND the
runtime state beside it (`.receiver.pid`, `.sessions/`) before the first test and asserting them
byte-identical after the last — the pattern already used in `test_milestone_overhead.py` (abb41fb).

## Acceptance criteria

1. The guard covers every class in the module regardless of name order (prove it with a
   deliberately-named last class that would have escaped the old guard).
2. Full suite green; `cairn check` ok; real data file and registry untouched.

### @architect — 2026-09-05

**GATE 1 RULING.** Seam: the held diff in `temp/2026-09-05-team-lead-pt91-guard-conversion.md` lands verbatim in `scripts/cairn/tests/test_otel_receiver_self_stop.py` (qa-engineer's file alone), **plus the three amendments below** — it does not pass AC 2 as written.

**Escape set (measured).** `unittest.TestLoader().loadTestsFromModule` on the module @93ba8ee: 16 classes / 32 tests, alphabetical. `RealDataFileUntouchedGuard` is index 10. Sorting after it, running outside the bracket — 5 classes / 9 tests: `SessionEndHookLineTests`, `SessionStartHookLineTests`, `StatusFourStateTests`, `TranscriptsDirMarkerPrecedenceTests`, `UnconditionalDeregistrationTests`.

**The gap is bigger than the Problem states.** The snapshot is taken in the guard's own `setUpClass` — after the 10 classes sorting *before* it have already run, so their writes are absorbed into the baseline and are invisible. The final check is `test_zz_real_file_unchanged_so_far`, a test *method* of that class. Net coverage: 1 of 16 classes (its own). 10 unobserved before the snapshot, 5 after the check.

**Construction.** Generated two throwaway modules (old class-scoped guard / new module-scoped guard), each with `AAAEarlyWriterTests` and `ZZZEscapeProbeTests` clobbering a fake "real" file, run under `python3 -m unittest`, fresh fixture per run. Old: `exit=0`, `Ran 4 tests`, `OK`, fixture left clobbered — the bug reproduced, green. New: `exit=1`, `FAILED (errors=1)` — caught. Both branches decisive. Harness: `scratchpad/pt91/gen.py`.

**Amendment 1 — the held diff's guard evaporates under `python -O`.** Measured on the same harness: new pattern `exit=1` without `-O`, **`exit=0` with `-O`** — `assert` is stripped at optimisation level 1. A guard whose firing depends on an interpreter flag is not a guard. `tearDownModule` must raise explicitly (`if after != _BEFORE: raise AssertionError(...)`), not bare `assert`. (Same defect is already shipped in `test_milestone_overhead.py:710,716` — out of scope here, bubbled up separately.)

**Amendment 2 — runtime state is missing.** The held diff snapshots only `token-usage.jsonl`. AC 2 requires "real data file **and registry** untouched" and the Ask names `.receiver.pid` and `.sessions/`. This module has no real-pidfile/real-sessions constants at all (only fake-root paths). Build adds them and snapshots all three, mirroring `test_milestone_overhead.py`'s `_snapshot_real_sessions_registry`.

**Amendment 3 — proof class (AC 1), two parts, both required.**
- `ZZZGuardCoverageProbeTests` — in-module, named to sort last. Writes **nothing**; asserts a module-level `_GUARD_ARMED` sentinel set by `setUpModule` is true at the time it runs. Satisfies AC 1's literal wording (a deliberately-named last class); would have failed under the old design, which had no module-level arming.
- `GuardBracketDifferentialTests` — the decisive proof, and an *independent* second implementation of the guard semantics rather than a re-read of ours. Generates both patterns into `tmp_path`, each with a last-sorting class writing to a **fake** "real" file, runs each as a subprocess, and asserts old→`returncode == 0` with the fake file modified (old guard misses it) and new→`returncode != 0` (new guard catches it). Run the new branch under `-O` too, asserting non-zero, so Amendment 1 stays fixed. Never touches the real file.

**Guard thresholds.** (a) Loader index of `ZZZGuardCoverageProbeTests` == `len(classes) - 1`, asserted via the loader, not by reading names. (b) `RealDataFileUntouchedGuard` absent from the module. (c) Exactly the guard's 2 test methods removed; no other test lost — state the final class/test count in the tests-red commit (baseline 16/32 → 30 tests + the two new classes). (d) Both differential branches assert an exit code, never just output text — a text-level check cannot distinguish "the guard fires" from "the guard exists".

**AC amendments in place.** AC 1 gains: the proof is a subprocess differential, not a text assertion. AC 2 gains: `.receiver.pid` and `.sessions/` are snapshotted alongside the data file, and the guard fires under `python -O`.
