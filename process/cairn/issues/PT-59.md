### @implementation-lead — 2026-08-28

Implemented per qa's red suite and team-lead's steer:

- `check_repo` now collects every milestone's `target_tag` (live +
  archived -- the same two-directory surface PT-54's release join reads)
  into one dict keyed by tag, threaded through the two loops that ALREADY
  read those directories for the GA-cap/archived-status checks -- no new
  directory read, no new helper (the "genuinely five-minute" case; PT-60
  still owns the broader milestone_paths single-sourcing for its own
  three call sites).
- Non-null tags shared by more than one record are an error, one per
  offending record, naming the shared tag + every sibling (archived ones
  marked "(archived)") -- same message shape as the existing GA-cap lint,
  the closest precedent for a cross-record multi-directory invariant here.
- Comparison is exact-string (case-sensitive, matches every other tag
  comparison in this codebase) and only ever runs on non-null tags.

Also fixed the collateral-damage class qa's test docstring flagged in
advance: `write_milestone`'s own default `target_tag` ("v1.0.0") collided
with `make_tree()`'s base milestone the instant this lint went live,
breaking `test_valid_definition_ids_pass`/`test_valid_development_ids_pass`
(15 subTest iterations). Flipped the default to null, same fix PT-41
applied to the `ga:true` default for the identical reason.
