#### The two things team-lead flagged, both verified clean

**1. Does the threading survive the loops' own early exits?** Read both collection
sites, then constructed the cases rather than trusting the read:

- **Archive loop** — its only `continue` is the `CairnError` parse failure, which
  sits *before* collection. Correct: an unparseable file has no readable
  `target_tag` to collect.
- **Live loop** — collection runs over `parsed_milestones` (already filtered of
  parse failures) and the loop body has **no `continue` at all**; the major checks
  are `if`/`elif`, so every parsed record reaches the collection.

Constructed both hazard shapes:

| Fixture | Result |
|---|---|
| malformed `PT-bad.md` sitting alongside a real duplicate pair | **2 duplicate errors still emitted** + the parse error ✓ |
| duplicate pair whose major is unknown (the `if`/`elif` branch) | **2 duplicate errors** + 2 unknown-major errors ✓ |

A future refactor turning either `elif` into a `continue` *would* silently drop
records from the lint. Worth a one-line comment at the live collection site
saying so — it's the failure mode this design is exposed to, and it's invisible
to every current test.

**2. Three-way collision emission.** Constructed 2 live + 1 archived on `v2.0.0`:

```
PT-c: target_tag 'v2.0.0' is shared with PT-a, PT-b, PT-c (archived) -- ...
PT-a: target_tag 'v2.0.0' is shared with PT-a, PT-b, PT-c (archived) -- ...
PT-b: target_tag 'v2.0.0' is shared with PT-a, PT-b, PT-c (archived) -- ...
```

Three errors, one per offender, each naming the full conflict set with the
archived record marked. No dedup loss, no missing sibling. Also verified:
case-sensitivity holds (`v1.0.0` vs `V1.0.0` → **0 errors**, correctly not a
collision), and null/absent tags are ignored.

#### Two cosmetic nits, neither worth blocking

- **Each offender names itself in its own sibling list** ("PT-1.0 … is shared
  with PT-1.0, PT-1.0b"). Slightly odd read — but there's a real argument for
  keeping it: a reader seeing *one* of three error lines gets the complete
  conflict set from that line alone. I'd leave it; recording the reasoning so
  it's a decision rather than an oversight.
- **Error order is archived-first, then live** (the archive loop collects first
  and insertion order is preserved), while the *sibling list* inside each message
  is sorted. Deterministic, so nothing flakes — but `for stem in sorted(stems)`
  at the emission site would make the two orderings agree for one word.

#### Scope note

`check_repo` takes a single `data_dir`, so this lint is per-repo — a tag shared
across two *roots* isn't checked. That matches the existing scope (secondary
roots are read-only, PT-3) and isn't a gap; noting it so nobody later reads the
1:1 guarantee as cross-root.
