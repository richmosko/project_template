## Problem

Bundle of non-blocking findings RECORDED during PT-29's Validate (architect diff review @ 0ce5647 + team-lead Chrome pass), none a regression:

1. **Chip sum < header total with "Show cancelled" on.** A cancelled issue counts toward `.swimlane-count` and `laneSummary.total` but has no `BOARD_COLUMNS` column and no chip — pre-existing (`.swimlane-count` was always `issues.length`), made visible by PT-29 putting the parts beside the whole.
2. **`.swimlane-header` lacks `flex-wrap`.** A collapsed lane with all five status chips populated below ~900px viewport crushes the milestone label instead of wrapping the chips. Repro needs a fully-populated lane at narrow width.
3. **`aria-expanded` without `aria-controls`.** The disclosed `.board` has no stable per-lane id to point at. Accessibility polish.
4. **Transient GET /api/board 503s at page load.** Two observed once during PT-29's Chrome pass; uncorrelated with toggles, not reproducible, curl 200. Suspected fetch/SSE connection race on the single-threaded server (PT-1 surface). Investigate only if seen again; wire in as a lint/log if cheap.

## Acceptance criteria

- [ ] Cancelled-count decision made explicit: either a "cancelled · n" chip when Show-cancelled is on, or total excludes non-column statuses — either way, chips sum to the visible total
- [ ] Chips wrap (or truncate gracefully) at narrow viewports without crushing the lane label
- [ ] `aria-controls` wired via stable per-lane ids on the disclosed containers
- [ ] 503 observation: reproduced-and-fixed, or closed as not-reproducible with a one-line note
