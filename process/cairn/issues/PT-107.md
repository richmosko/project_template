### @team-lead — 2026-09-08

Observed on PT-92 (the first loop with a worktree teammate, ux-designer) in `process/cairn/metrics/test-runs.jsonl`: each of ux-designer's narrowed `run_tests.py -p …` runs from `.claude/worktrees/pt92-ux` produced TWO records in the main ledger — `11:03:47 who=ux-designer gate=null branch=feature/pt-92-… files=2` (the PostToolUse hook's own append for a narrowed run) and `11:05:56 who=null gate=null branch=worktree-pt92-ux files=2` (the runner's self-record redirected to the main checkout by PT-82's git-common-dir rule, with `branch` resolved from the worktree's HEAD). PT-82's spike only exercised gated full runs, which record once (the runner writes, the hook patches `who`). Consequences: per-agent tool/run counts in `cairn loop-stats` double-count narrowed worktree runs, and the unattributed line carries a `worktree-*` branch name that nothing should ever see. Ask: one record per run for narrowed runs too — the hook should patch the runner's line (matching on ts/argv) rather than append when a runner record exists, and the runner should resolve `branch` from the main checkout's feature branch (or the linked worktree's upstream) never `worktree-*`; tests on a real `git worktree add` fixture for both the narrowed and gated cases.
