## Problem

Spun out of PT-31 item 1 (architect triage, 2026-08-22): with "Show cancelled" checked, kanban admits cancelled issues that render in NO column — columnsFor builds from BOARD_COLUMNS only — so the checkbox is inert in kanban view and an expanded lane's count exceeds its visible cards (predates PT-29). PT-31 fixes the arithmetic (counts = column-backed statuses only); the honest root fix is a conditional sixth column, which is layout work: it makes BOARD_COLUMNS conditional and ripples into laneSummary's purity contract.

## Acceptance criteria

- [x] Architect design ruling first (conditional-column mechanics vs BOARD_COLUMNS purity)
- [ ] With Show-cancelled on, cancelled issues visibly render in kanban; counts consistent
- [ ] Show-cancelled off: zero behavioral or DOM change

### 0. Ground truth — the ripple is smaller than the issue implies, and one part of it is already fixed

- **`BOARD_COLUMNS` has exactly two production consumers.** `columnsFor`
  (board.js:648) and `laneSummary` (board-logic.js:540). That is the entire
  ripple. Everything else — chips, drag targets, the chip-sum invariant —
  reaches `BOARD_COLUMNS` *through* one of those two, which is why this is
  tractable.
- **List view is already correct.** `renderList` (board.js:976) renders
  `filteredIssues()` straight into a table with no column mapping, so a
  cancelled issue already appears there with Show-cancelled on. **The bug is
  kanban-only.** Do not "fix" list view.
- **The server already accepts the status.** `STATUSES` (cairn.py:58) includes
  `"cancelled"`. A drag into a cancelled column is an ordinary `PATCH` — no
  server change, no new endpoint. This decides § 5.
- **The ordering convention already exists, in the other language.**
  `cairn.py:1277` builds `list(DEFAULT_COLUMNS) + ["cancelled"]` for the
  milestone report's status grouping. Cancelled goes **last, after done**.
  Mirror it rather than inventing a second convention.
- **No CSS is needed.** `.board` is `display: flex; gap; overflow-x: auto`
  (board.css:271–273) and `.column` is `flex: 1 1 0; min-width: 220px`
  (board.css:276–283). A sixth column flexes and, past the wrap point,
  scrolls — there is no column-count constant anywhere in the stylesheet.
- **The label already exists.** `STATUS_LABELS.cancelled` = `"Cancelled"`
  (board.js:92), so the column header needs nothing added.
- **Collapsed chips need no CSS either.** The summary chip is built with
  `chip("", …)` (board.js:743) — no per-status class, unlike `.chip.assignee`
  / `.chip.blocked` etc. A Cancelled chip inherits the base `.chip` style.

So the work is: one pure derivation, one signature change, one read path, and
a threading pass. Not a layout project.

### 1. Composition — a pure derivation plus a single read path, not a second constant

**Rejected: a second exported constant** (`BOARD_COLUMNS_WITH_CANCELLED`).
Two exported lists is the drift class PT-22's extraction pass and PT-29's
"single canonical copy" comment exist to close. Whatever derives one from the
other is the real answer, so export *that*.

**Rejected: mutating `BOARD_COLUMNS` per render.** Kills the purity contract
outright and makes every pure function in board-logic.js secretly
state-dependent.

**Ruling — three pieces:**

```js
// board-logic.js — the pure derivation. BOARD_COLUMNS stays exactly as it is.
function boardColumns(showCancelled) {
  return showCancelled ? BOARD_COLUMNS.concat(["cancelled"]) : BOARD_COLUMNS;
}
```

```js
// board.js — the SINGLE read path, same pattern PT-29 established for
// laneExpanded. Not a cached variable; a function.
function activeColumns() { return boardColumns(state.showCancelled); }
```

```js
// board-logic.js — laneSummary takes the set EXPLICITLY.
function laneSummary(issues, columns) { … }
```

**Why a function and not a render-scoped cached variable.** A `var
activeColumns` assigned at the top of `render()` is one derivation, but it is
also a stale-cache surface and a rule — "remember to set this at the top of
every render path" — that a new render path can quietly violate. A function of
`state.showCancelled` cannot be stale and cannot disagree with itself. Every
consumer computes the same pure function of the same input, so **"counted iff
rendered" holds by construction**, which is exactly what AC2 asks for. This
also matches the house pattern: PT-29 ruled `laneExpanded` "the SINGLE read
path" for `state.expandedLanes` for the same reason.

> **Judgment call (JC4).** Recomputing per call rather than once per render.
> Cost: a ternary per call, plus one six-element allocation per call *when
> Show-cancelled is on* (when off it returns the shared array with no
> allocation at all — see § 3). There are five call sites; this is noise.
> Reversal: hoist to a render-scoped var and accept the stale-cache surface.

---

### 2. `laneSummary`'s second argument is REQUIRED, and its absence must throw

```js
function laneSummary(issues, columns) {
  if (!Array.isArray(columns)) {
    throw new TypeError("laneSummary: `columns` is required — pass activeColumns()");
  }
  …
}
```

**Do not give it a default of `BOARD_COLUMNS`.** A default means a call site
that forgets the argument silently counts five columns while the board renders
six — an undercount in the lane header against visible cards. That is
*precisely* the defect PT-31 shipped a fix for and precisely what AC2 forbids,
and it would be invisible until someone counted cards by hand.

> **Judgment call (JC1).** A throw in a render path means a missed call site
> takes the whole board down instead of showing a slightly wrong number. I am
> choosing loud-and-total over quiet-and-wrong: every call site is in this
> repo, the failure is a programmer error reachable only at development time,
> and the node suite catches it on the first run. This board has now twice
> shipped a silently-wrong count; a third time is not worth avoiding a stack
> trace. Cost: as stated. Reversal: `columns || BOARD_COLUMNS`, one token.

### 3. AC3 ("Show-cancelled off = zero behavioral or DOM change") — structurally enforced

The enforcement is **reference identity**, not a comparison of behaviours:

`boardColumns(false)` returns **`BOARD_COLUMNS` itself** — the same array
object, not a copy. So with the checkbox off, `columnsFor` iterates the
identical array the pre-PT-35 code iterated and `laneSummary` sums over the
identical list. There is no code path in which "off" and "before this change"
can differ, because they are the same values flowing through the same loops.

QA's red is an identity assertion, not a deep-equal:
`assert.strictEqual(boardColumns(false), CairnLogic.BOARD_COLUMNS)`.

A deep-equal would pass for a copy, and a copy is what a well-meaning
refactor to `BOARD_COLUMNS.slice()` would produce — at which point the
guarantee quietly degrades from "identical" to "equal today". Pin the identity.

**Combined with the measured facts in § 0** (no CSS change, no new label, no
new chip class, list view untouched, no server change), AC3 reduces to: does
any *other* line of the diff execute differently when the flag is off? The
answer must be no, and the diff should be reviewable for that in one pass.

### 4. What the counts mean with Show-cancelled on

`laneSummary`'s contract is unchanged in shape: `total` is the sum of
`byStatus`, `byStatus` enumerates the passed column set in order and omits
zero counts. With `columns` including `"cancelled"`, cancelled issues count
toward `total` and get a chip.

This **preserves PT-31's fix rather than reverting it.** PT-31's rule was
never "cancelled doesn't count" — it was *counted iff column-backed*. PT-35
makes cancelled column-backed when the flag is on, so the same rule now yields
a different, still-correct answer. The invariant the code must keep is the one
PT-31 stated: **`total` is the sum of `byStatus`, and both back the same
render.** Say so in the comment, because a reader who knows PT-31 only as
"cancelled is excluded" will think this reverts it.

Two consequences to state explicitly so nobody "fixes" them:

- **A lane whose issues are all cancelled** reads `0` with the flag off (its
  cards are filtered out upstream by `filteredIssues`, board.js:354 — nothing
  is hidden) and `N` with the flag on, with one `Cancelled · N` chip. That
  transition is the feature working.
- **A lane with zero cancelled issues, flag on**, renders an *empty Cancelled
  column* (`—`) but **no Cancelled chip** — `byStatus` omits zero counts while
  `columnsFor` always renders every column. This asymmetry is pre-existing and
  identical for the other five columns. Leave it.

### 5. Drag-and-drop — cancelled is a status, so its column is a drop target like any other

**Ruling: cards can be dragged INTO cancelled and OUT of it, with no
special-casing.** `makeColumn` attaches `dragover`/`drop` unconditionally and
`handleDrop` PATCHes `status`; the server accepts `"cancelled"` (§ 0). So the
correct implementation is *no code* — the sixth column inherits the behaviour.

The alternative (a read-only column) costs a new conditional in `makeColumn`,
a new affordance to explain why one column rejects drops, and an asymmetry
where you can drag a card in but not out — or out but not in — neither of
which has a principled stopping point.

Cancel-by-drag is reversible in one drag, deletes nothing, and already routes
through the existing optimistic-update + 409-reconciliation + toast path.
`isDraggable` still governs foreign-root refusal for both directions, unchanged.

> **Judgment call (JC3).** Cost: an accidental drop into Cancelled changes an
> issue's status, and "cancelled" reads as more consequential than the other
> transitions even though mechanically it is not. Reversal: gate the `drop`
> and `dragover` listeners on `status !== "cancelled"` inside `makeColumn` —
> one condition, and the column becomes display-only.

### 8. Red-first test surface — QA's lane

**Pure (`node:test`, board-logic.js):**

1. `boardColumns(false)` **is** `BOARD_COLUMNS` — `strictEqual`, reference identity, not deep-equal (§ 3)
2. `boardColumns(true)` deep-equals `["backlog","todo","in-progress","in-review","done","cancelled"]` — cancelled **last**, mirroring cairn.py:1277
3. `boardColumns(true)` does not mutate `BOARD_COLUMNS` (assert the constant after the call)
4. `boardColumns(true)` returns a fresh array on each call (two calls, not `strictEqual`)
5. `laneSummary(issues, undefined)` **throws** `TypeError`; likewise for a non-array (§ 2)
6. `laneSummary(issues, boardColumns(false))` excludes cancelled from `total` and `byStatus` — the PT-31 behaviour, unchanged
7. `laneSummary(issues, boardColumns(true))` **includes** cancelled in `total` and emits a `{status:"cancelled", count}` entry **last** in `byStatus`
8. chip-sum invariant holds in both: `byStatus.reduce(sum) === total`, asserted for both column sets — PT-31's invariant must survive the new set, not just the old one
9. zero cancelled + `boardColumns(true)` ⇒ **no** `{status:"cancelled", count:0}` entry (the omit-zero rule applies to the new column too, § 4)
10. a status in neither set (e.g. `"archived"`) is still excluded from `total` under `boardColumns(true)` — the rule is "column-backed", not "not-cancelled"
11. existing `lane-summary.test.js` cases pass with `, CairnLogic.BOARD_COLUMNS` threaded and **no expected value altered** (§ 6, JC5)

**Browser pass (Chrome):** (a) flag off — kanban identical to before, six-column layout nowhere; (b) flag on — cancelled cards appear in a sixth column, lane header count matches visible cards **counted by hand**, which is the AC2 check and the one that actually failed before; (c) collapse a lane containing cancelled ⇒ `Cancelled · N` chip, chips sum to the header count; (d) drag a card into Cancelled ⇒ status persists across a reload; (e) drag it back out ⇒ persists; (f) toggle the checkbox off while a cancelled card is on screen ⇒ it disappears and counts drop consistently; (g) multi-root: check a repo section in **both** swimlane and flat sub-paths; (h) narrow the viewport with six columns and report what horizontal scrolling feels like (OQ2).

### 9. Open questions — measure, don't guess

1. **Should the Cancelled column be visually de-emphasized** (dimmed header,
   muted cards) to signal terminality? Plausibly yes, but I am **not**
   specifying styling from an estimate — I have made that mistake before.
   Judge it in the Chrome pass with the column on screen; if it wants
   de-emphasis, that is a one-rule follow-up, not part of this diff.
2. **Six columns at a narrow viewport.** `min-width: 220px` × 6 + `12px` × 5
   ⇒ horizontal scrolling begins around **1380px** of board width, against
   ~1160px for five. That arithmetic is from the measured CSS values, but
   whether it is *unpleasant* at a common window size is a judgment that needs
   eyes. If it is: the answer is **not** shrinking `min-width` (that hurts all
   six columns to fix one); report the measurement and we will decide.
3. **`DEFAULT_COLUMNS` (cairn.py:57) and `BOARD_COLUMNS` (board-logic.js:466)
   are the same list maintained in two languages**, and after this change the
   `+ ["cancelled"]` append rule is duplicated too (cairn.py:1277 and
   `boardColumns`). Out of scope here — flagging for a future issue, since the
   drift would be silent and cross-language.
