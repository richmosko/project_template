### @team-lead — 2026-09-08

Architect's measured finding on PT-116's ruling @8c1cc29 (2026-09-09): the `.claude/settings.json` sh prefilter matches on the Bash command TEXT (`*run_tests*`, `*unittest*`), so a run invoked indirectly — `sh probe.sh` whose body runs `run_tests.py` or `python3 -m unittest discover` — reaches neither the PreToolUse guard nor the PostToolUse record hook: no refusal for an un-tiered full run, no ledger record, invisible to loop-stats. Fix candidates: (a) the runner self-records regardless of the hook (already true for `run_tests.py`; bare unittest has no self-record), so the residual is the guard: make `run_tests.py` itself refuse an un-tiered full run when it detects it is being driven by a teammate (`CLAUDE_CODE_AGENT_TYPE` or the session env) — the guard moves from command text to the runner; (b) accept the gap and document it in the guard's docstring as a known bypass. Backlog (filed during the PT-0.12.2 backlog drive; Mosko routes).
