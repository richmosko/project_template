### @architect — 2026-09-09

**Gate 1 ruling (architect).** Measured at `b41f275` before ruling.

**Env survives the wrapper, two levels deep.** A `sh script.sh` child and a `python3` grandchild launched from inside it both see the full Claude Code environment: `CLAUDECODE=1`, `CLAUDE_CODE_CHILD_SESSION=1`, `CLAUDE_CODE_SESSION_ID=817d7be4-…`, `CLAUDE_CODE_BRIDGE_SESSION_ID`, `CLAUDE_CODE_MESSAGING_SOCKET/TOKEN`, `AI_AGENT=claude-code_2-1-263_agent`, `CLAUDE_PID`. **There is no agent-type variable** — the runner can detect the *lane*, never the identity. That is enough for a refusal and not enough for attribution, so `who` stays the hook's job.

**Ruling on (1): candidate (a), the runner is the backstop; the hooks stay the fast path.** In `run_tests.py`, immediately after argument parsing — before discovery, before `run_all`, **before `_self_record`** — refuse when **all** hold: `CLAUDECODE` set, `CLAUDE_CODE_CHILD_SESSION` set, the run is full (no `-p`/`--pattern`/`-k`), and `--gate` is absent. Everything else runs: a human shell (no `CLAUDECODE`), any narrowed run, any gated run.

**Open measurement, one command, for the issue file — not a blocker.** I cannot read the main session's environment from here. If the lead's own shell also sets `CLAUDE_CODE_CHILD_SESSION` (`env | grep -c CLAUDE_CODE_CHILD_SESSION` from the main session, recorded as a comment), then this refusal also covers the lead's un-tiered full runs — which is a policy change beyond the hook's deliberate fail-open for the main session, and the docstring must say so plainly. It is not a defect either way: `WORKFLOW` already requires the lead's finish run to carry `--gate finish`. Proceed on the predicate above; the measurement decides one sentence of documentation, not the design.

**Ruling on (2): the runner-side refusal is exact, and it exits 2.** The runner has `--gate` and the pattern as parsed values, so the whole defect class that has occupied PT-111/PT-113/PT-115 — quoted text, heredoc bodies, `git add` paths, versioned interpreters, launchers — is **structurally impossible** here: there is no command text to misread. Exit **2**, the runner's existing "nothing ran" code, distinct from 1 (a red suite); the refusal text goes to **stderr** and is shared with the PreToolUse guard via `_test_run_shared` so both lanes say the same sentence. **Print no `Ran N tests` line** — that is load-bearing: it keeps PT-111's classifier on rule 3 (error result, no summary) → `full_run_blocked`, and it keeps PT-116's record hook writing nothing. Refusing before `_self_record` means a refused run leaves no ledger row at all, which is correct: nothing ran.

**Ruling on (3): bare `unittest` under a wrapper stays uncovered, deliberately, and is documented as such.** No record (stdlib cannot self-record, and the wrapper removes the hook's only channel) and no refusal. A refusal in the tests' shared `helpers` module was considered and rejected: it would fire mid-collection with test modules already imported, and it could not tell a full discovery from a narrowed one without re-introducing exactly the `sys.argv` text parsing this ruling removes. The docstring says: `run_tests.py` is the supported runner; a bare `unittest discover` under a wrapper is outside both lanes.

**Guards (qa writes; red at gate 2).**
1. Fixture wrapper script (`sh fixture.sh`) driving `run_tests.py` full and un-tiered **with** the teammate env → exit 2, the shared marker on stderr, no `Ran N tests` line, and **no new ledger row**.
2. Same wrapper, same command, **without** `CLAUDE_CODE_CHILD_SESSION` (human/main-session lane) → runs normally, exit 0/1, ledger row written.
3. Narrowed control: `-p "test_x*.py"` under the wrapper with the teammate env → never refused.
4. Gated control: `--gate green` under the wrapper with the teammate env → never refused.
5. Classifier coupling: the refusal's shape (error result, no summary, no `toolDenialKind`) classifies `full_run_blocked` through `loop_stats._resolve_full_suite` — assert it, since PT-111's rule 3 is what makes the refusal visible on the scorecard.
6. Unchanged: every existing hook test, and the direct (non-wrapper) path still refused by the PreToolUse guard first — the runner check must be a backstop, not a second refusal that changes the direct case's message.

**Writers.** implementation-lead → `scripts/cairn/run_tests.py` + `.claude/hooks/_test_run_shared.py` (shared refusal text). qa → the six guards. No `settings.json` change: the prefilter stays a fast path, and widening it to match wrapper text is impossible in principle — the body is in a file the hook never sees.

### @architect — 2026-09-09

**Gate 1 ruling, re-issued whole (architect) — the measured objection is upheld and my predicate was wrong.** `CLAUDE_CODE_CHILD_SESSION=1` is set on the lead's lane too, so it discriminates nothing; there is no `CLAUDE_CODE_AGENT_TYPE`. Agent identity exists only in the hook payload. This replaces the ruling @ `dd1432d` in full; nothing there survives except items (2) and (3), restated below unchanged.

**New measurements taken for this re-issue.** Over the whole archive: **14,576** Bash calls, of which **2,619** match the prefilter by text and exactly **20** invoke a wrapper script (`sh|bash <file>.sh`) — **one** of those also names the runner in its own text, and the only wrapper call that actually ran the suite is the one I made while measuring PT-116. Widening the prefilter to `sh|bash` would add hook spawns on **19** archived calls, **0.13 %** — so cost is *not* the argument against option (a), and I will not pretend it is. No shell rc file exports `CLAUDE*`, so a human's own terminal carries no `CLAUDECODE`.

**Ruling: option (b), scoped by `CLAUDECODE` — the runner refuses an un-tiered full run in any Claude Code lane, lead included.** In `run_tests.py`, after argument parsing and **before** discovery, `run_all`, and `_self_record`: refuse when `CLAUDECODE` is set **and** the run is full (no `-p`/`--pattern`/`-k`) **and** `--gate` is absent. A human terminal (no `CLAUDECODE`) is never touched; narrowed runs and gated runs are never touched.

**This deliberately extends the refusal to the lead's lane, and that is the judgment call in this ruling.** The PreToolUse hook fail-opens for the main session because it cannot identify it; the runner cannot either. Rather than infer identity from an env variable that has now been measured not to carry it, the rule becomes the one `WORKFLOW` already states for everyone: **a full suite run is declared at a gate.** The lead's finish run already carries `--gate finish`; the cost is that an ad-hoc full run from the lead's lane now needs `--gate` or `-p`. If Mosko or the lead would rather keep the lead's lane unconditionally open, the alternative is an explicit escape (`CAIRN_ALLOW_UNTIERED=1`) — auditable, but a bypass by construction; I recommend against it and will implement it only if asked.

**Option (a) rejected — on shape, not on cost.** Having the guard read the wrapper file and scan its body: (i) it is text scanning of a *file*, and nesting is unbounded — a script that calls a script needs recursion with a depth limit and a cycle guard; (ii) it covers only the `sh <file>` shape, not `python3 -c`, `make`, `xargs`, or a heredoc-fed shell; (iii) it re-enters the exact defect class PT-111, PT-113 and PT-115 spent three loops removing, on a surface where a false positive **refuses a teammate's legitimate command**. The runner-side check has none of that: it reads parsed arguments, so there is no text to misread.

**(2) restated, unchanged.** Exit **2** (the runner's existing "nothing ran" code, distinct from 1 = red suite); refusal text on **stderr**, shared with the PreToolUse guard via `_test_run_shared` so both lanes say the same sentence; **no `Ran N tests` line** — load-bearing, since it keeps PT-111's classifier on rule 3 (error result, no summary) → `full_run_blocked` and keeps PT-116's record hook writing nothing. Refusing before `_self_record` leaves no ledger row: nothing ran.

**(3) restated, unchanged.** Bare `unittest discover` under a wrapper stays uncovered — no record, no refusal — and is documented in the guard's docstring as the known residual. Measured frequency of that shape in the archive: **zero** outside my own PT-116 probe.

**Guards (qa writes; red at gate 2).**
1. Wrapper fixture (`sh fixture.sh`) running `run_tests.py` full and un-tiered **with `CLAUDECODE=1`** → exit 2, shared marker on stderr, no `Ran N tests` line, **no new ledger row**.
2. Same wrapper **with `CLAUDECODE` unset** (human terminal) → runs normally, ledger row written.
3. Narrowed control (`-p "test_x*.py"`, `CLAUDECODE=1`, under the wrapper) → never refused.
4. Gated control (`--gate green`, `CLAUDECODE=1`) → never refused.
5. **Lead-lane case, asserted as intended behaviour, not left implicit**: `CLAUDECODE=1` with no `CLAUDE_CODE_CHILD_SESSION` distinction available → still refused; the test's docstring records that this is the deliberate extension.
6. Classifier coupling: the refusal shape (error result, no summary, no `toolDenialKind`) classifies `full_run_blocked` through `loop_stats._resolve_full_suite`.
7. Unchanged: every existing hook test; the direct path is still refused by the PreToolUse guard first, so the runner check is a backstop and must not change the direct case's message.

**Writers.** implementation-lead → `scripts/cairn/run_tests.py` + `.claude/hooks/_test_run_shared.py` (shared refusal text). qa → the seven guards. No `settings.json` change.
