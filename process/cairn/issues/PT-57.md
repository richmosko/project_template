### @architect — 2026-08-27

## Token-delivery ruling

Investigated `board.css` (875 lines, **21 distinct hex literals**), the spec's
Legacy/migration + Project-extensions tables, `docs/DESIGN/tokens.css`, the
server's static path, and every test that reads `board.css`. Measurements decide
most of this.

### 1. Delivery: a new `scripts/cairn/board/tokens.css`, linked from board.html

`<link rel="stylesheet" href="/board/tokens.css">` **before** `board.css`.

Why this and not the alternatives:
- **Zero server changes.** `/board/<rel>` already serves anything under
  `BOARD_DIR` through the existing guarded `_send_static`. Serving
  `docs/DESIGN/tokens.css` instead would need a new route *and* would make the
  board depend on `docs/` — a template concept cairn must not read, and a
  dependency that breaks the moment cairn is spun off or a cloner prunes docs.
- **Not inlined into `board.css`.** A standalone file makes the copy a
  *verbatim block* that a parity test can compare declaration-for-declaration,
  instead of a regex extraction from an 875-line stylesheet.
- **Not the dashboard's built CSS.** `dist/assets/index.css` carries the tokens
  but also the whole Tailwind bundle (preflight included), which would fight
  board.css directly. Rejected outright.

**This is a third copy of the token values** (reference `tokens.css`, the
dashboard's `app.css`, now the board's). That is the PT-36 question and it gets
the PT-36 answer: **where a copy is unavoidable, make drift loud.** Ship a
parity test that parses the `:root` and `.dark` declarations from all three and
asserts they agree. Copies are survivable; *silent* copies are not.

### 2. Fonts: **out of scope for PT-57.** Colors and radius only.

Not a deferral by preference — by AC. This issue's criteria are "consumes
`tokens.css` variables; legacy hexes gone" and it is a **P3 ridealong, explicitly
not a release blocker**. Adding font binaries expands a P3 into a payload change.

**The follow-up is pre-decided so it's cheap when someone wants it:** three
faces, **latin + latin-ext subsets only**, six `.woff2` files (~245KB) committed
to `scripts/cairn/board/fonts/`, with `@font-face` declared in
`board/tokens.css`. Self-contained, offline, no build — the board's zero-network
contract intact.

**Explicitly rejected, now and later: pointing the board's `@font-face` at
`/dashboard/assets/*.woff2`.** It costs no bytes, and that's the trap — it makes
the *board's rendering* depend on the dashboard's build artifact. That's the
dependency direction the spin-off constraint forbids, and it would make an
unbuilt dist degrade the board as well as the dashboard.

Until then the type seam is honest, and the embed panel already carries a line
saying the board keeps legacy styling.

### 3. The mapping — full enumeration, no improvisation needed

**⚠ The highest-risk item first: `--accent` changes meaning.** `board.css` uses
`--accent` as its **primary blue** (`#0052cc`) — active tabs, `+ New`, submit
buttons, drawer action buttons, the in-progress dot, the assignee chip's text.
The preset's `--accent` is a **near-white hover/active surface**
(`oklch(0.97 0.001 106.424)`). Link tokens.css without rewriting those call
sites and every primary action silently turns near-white on white. **Every
`var(--accent)` in board.css becomes `var(--primary)`.** `--border` and
`--radius` keep their names and change values, which is fine; `--accent` is the
one that must not.

**Chips** (spec → Project extensions, variant weight not hue):

| Selector | Variant | Fill / text |
|---|---|---|
| `.chip` (base), `.chip.milestone`, `.chip.subissues`, `.chip.progress` | `outline` | transparent, `--border` outline, `--muted-foreground` |
| `.chip.assignee`, `.chip.release` | `secondary` | `--secondary` / `--secondary-foreground` |
| `.chip.repo` | `outline` + keep `--font-mono` | family is a label distinction, not a hue |
| `.chip.blocked` | `destructive` | `--destructive` / `--destructive-foreground` |
| `.chip.archived` | `outline` + italic + `opacity: 0.6` | keep the existing treatment — the spec names exactly this |
| `.chip.ga` | `default` + keep `font-weight: 600` | `--primary` / `--primary-foreground`. Not in the spec's table; ruled here: GA is the one milestone marker that should dominate, which is what `default` weight is for |

**Record statuses** — `.chip.status[data-status=…]`, straight from the spec's
record-status table:

| status | fill / text |
|---|---|
| `planned` | transparent + `--border` outline, `--muted-foreground` |
| `in-progress` | `--primary` / `--primary-foreground` |
| `paused` | `--chart-2` / `--foreground` |
| `done` | `--foreground` / `--background` (inverted) |
| `cancelled` | `--destructive` / `--destructive-foreground` |

**Status dots** — `.major-status-dot[data-status=…]`, the table's Dot/accent
column: `planned` → `--ring`; `in-progress` → `--primary`; `paused` →
`--chart-2`; `done` → `--foreground`; `cancelled` → `--destructive`; **default /
unknown-no-record** → `--muted-foreground` (no spec row; ruled here — it is
absence, not a status, so it takes the lowest-weight neutral).

**The remaining literals**, each by role: `--bg` → `--muted` (the spec's
cards-on-muted canvas convention); `--panel` → `--card`; `--text` →
`--foreground`; `--text-dim` → `--muted-foreground`; `--danger` →
`--destructive`; `.connection-state.live` `#00875a` → `--primary` (it is a
liveness indicator, and the system has no green); `table.issue-list tr:hover`
`#f4f5f7` → `--accent` (this **is** the preset's hover-surface role — the one
place `--accent` is correct); the seven `color: #fff` on filled elements → the
matching `*-foreground` for whatever fills them, **never a blanket
`--background`**.

**Test impact — verified, not assumed: none.** All three JS tests that read
`board.css` assert on **selectors and structure**, never on colors:
`archived-badge-surfaces` matches `/\.majors-tabs\s+button\.is-archived/`,
`progress-strip-removed` asserts a rule's *absence*, and
`embed-visibility-scope` extracts the `body.<token>` rule and its
`display: none` selector list. A colors-only migration breaks none of them —
**provided no selector is renamed or removed.** That is a constraint on this
work, not an observation.

**Add one guard while you're in here:** assert that every `var(--x)` referenced
in `board.css` is defined in `board/tokens.css` or in board.css's own retained
`:root`. That single test catches the `--accent` collision class, typos, and any
future token the board reaches for but nobody ships.

### 4. What must NOT migrate

**Colors, radius, and shadows only. Everything else keeps its structure.**

- **The PT-32 pull-indicator stack** — `translateY(-100%)` rest state, `z-index`
  11-over-10, the offset cap. That geometry was derived empirically after a
  ruling of mine got it wrong; it is not styling.
- **PT-49's engine-stale banner**, its persistence and placement.
- **Sticky header, `position: fixed` drawer/toast/overlay, `overflow` on the
  column strip, `overscroll-behavior-y: contain`** (load-bearing against
  Android Chrome's native pull-to-refresh, per its own comment).
- **`opacity: 0.6` + italic** on `.card.is-archived`, `.chip.archived`, and
  `.majors-tabs button.is-archived` — the spec endorses exactly this treatment;
  don't replace it with a token.
- **Every selector name.** No renames, no consolidation, no deletions (see test
  impact).
- **Retained `:root` entries:** `--card-gap`, `--col-gap`, `--shadow`. Layout
  spacing and the shadow are not preset tokens; keep them local and map the
  shadow by eye to the spec's `shadow-sm`/`shadow-md` guidance rather than
  inventing a token.
- **`--radius` is not a 1:1 swap.** The old value is 6px; the preset's is
  0.625rem/10px with a scale. Per the spec's radius table, pick per component —
  badge/chip `--radius-sm`, buttons/inputs `--radius-md`, cards/drawer
  `--radius-lg`. Don't blanket-replace.

### Addendum — three gaps implementation-lead's recon found, closed

Their recon crossed with the ruling above. Most of it lands on the same
answers (chip taxonomy, the `--accent` collision, `#00875a` having no green to
migrate to), but it surfaces **three things the ruling didn't cover**. Closing
them here rather than leaving them to improvisation.

#### 1. NEW — the navy-tinted overlay and shadow literals

I enumerated hex literals and missed the `rgba()` ones. Verified, three of them:

```
:root  --shadow: 0 1px 2px rgba(9, 30, 66, 0.12);
.drawer-overlay  background: rgba(9, 30, 66, 0.35);
.drawer          box-shadow: -4px 0 16px rgba(9, 30, 66, 0.15);
```

`rgb(9, 30, 66)` is Atlassian navy — a **carried-forward hue**, which the
preset-pure direction forbids as much as any hex. The preset ships no overlay
token and shadcn's own convention is plain black at an alpha.

**Ruled: drop the tint, keep the alphas.** `rgba(0, 0, 0, 0.35)` for the scrim,
`rgba(0, 0, 0, 0.12)` / `rgba(0, 0, 0, 0.15)` for the shadows. Same perceived
depth, no inherited hue. This is the last place the retired palette would have
survived the migration, and it would have survived invisibly — grep for `#` and
it isn't there.

#### 2. The dot rule, stated as a rule rather than a table

Fair challenge: the record-status vocabulary defines **badge fills**, and a 6px
solid dot isn't a badge. The rule, so future statuses don't need a new ruling:

> **A status dot takes its badge variant's *fill* token.** Where the variant has
> no fill (`outline`), it takes `--ring`.

That generates exactly the table in the ruling above — `planned` → `--ring`,
`in-progress` → `--primary`, `paused` → `--chart-2`, `done` → `--foreground`,
`cancelled` → `--destructive` — and it generates the right answer for any status
added later. The no-record/unknown default stays `--muted-foreground`: absence
is not a status.

#### 3. Fonts follow-up: the vendor precedent is the better shape — adopted

My pre-decision said `board/fonts/`. The recon points at
`scripts/cairn/board/vendor/`, which already solves exactly this problem
(checked-in third-party binaries, zero CDN, zero build) **and carries a
`NOTICE.md` recording library, version, license, and upstream URL per file**.

**Adopted, refining the earlier pre-decision:** when fonts happen, they go to
`scripts/cairn/board/vendor/fonts/` with `NOTICE.md` rows for each — the three
faces are third-party assets under the **SIL Open Font License**, so they need
the provenance treatment more than a JS bundle does, not less. Subsets and file
count unchanged (latin + latin-ext, six woff2, ~245KB); `@font-face` still lives
in `board/tokens.css`.

**Still out of scope for PT-57** — the AC is colors-and-badges on a P3
ridealong. I'm recording the refined shape now so the follow-up is a mechanical
task rather than another ruling.

#### Confirmations on the recon's open questions

- **`--col-gap` / `--card-gap` are out of scope — confirmed.** They're layout
  spacing, not color; the AC doesn't touch sizing. Keep them in board.css's
  retained `:root` exactly as they are.
- **`--accent` and `--radius` must leave board.css's `:root` entirely**, not be
  repointed. Once `board/tokens.css` is in the cascade both names resolve to
  preset values, so a surviving local declaration is a coin-flip on load order.
  Delete both; rewrite call sites (`--accent` → `--primary`, except
  `table.issue-list tr:hover` where the preset's hover-surface role is genuinely
  correct; `--radius` → the per-component scale).
- **`.connection-state.live` → `--primary`** — already ruled above, and the
  recon's framing is right about why it needed a call: it is *not* a record
  status, so the Done-inverted treatment doesn't apply to it. It's a liveness
  affordance, `--primary` is the system's one "this is live and good" weight, and
  the alternative (inverted `--foreground`) would make a connection indicator
  look like a completed record.
- **The seven `color: #fff` declarations** are covered by the ruling's
  "matching `*-foreground` for whatever fills them" clause — per-fill, never a
  blanket value.

#### ⚠ Correction for qa before the guard is written

**The guard as dispatched — "top-level rule floor, balanced braces" — would have
PASSED this file.** Measured, not predicted: my own comment-aware scanner reports
**126 top-level rules and balanced braces (depth 0)** on the broken board.css. A
rule-count floor and a brace check both succeed, because the early close doesn't
unbalance anything structurally; it just relocates where "code" begins.

The predicates that actually decide it, both cheap:

1. **Raw delimiter counts must be equal** — `count("/*") == count("*/")`. 42 vs 43
   here. This is the direct expression of "there is a stray closer."
2. **No `*/` glued to a non-whitespace character** — regex `\S\*/`. This is the
   one that pinpoints *which* line, which a count alone can't. It fires on line 6
   and nowhere else in the repo.

Keep the stray-`*/` check from the dispatch — it's the right idea; the rule floor
and brace balance are the two legs that don't work. Both proposed predicates are
born red against the current file, so the red-first requirement holds.

Applying the same logic to prose: the pattern to audit for is not "`*/` in a
comment" but "**any `*` immediately followed by `/`**" anywhere inside comment
prose — `--chart-*` + `/--radius` is invisible to a human scanning for `*/` as a
token, because neither character belongs to the closer conceptually.

#### What this says about the gate structure

The team-lead's note is right and worth stating in the ruling record: **all 384 JS
tests read board.css as text.** A stylesheet the browser treats as one giant
comment satisfies every textual assertion, including my own review's — I verified
zero legacy hexes, exactly one `var(--accent)`, correct token parity, preserved
structure, and *every one of those facts was true* about a file that rendered
nothing. Text-level verification cannot distinguish "the rules say the right
thing" from "the rules exist."

That is the third catch for the manual browser leg in three features, and the
first that no automated gate here could have caught even in principle without a
CSS parser. I'd support making a parse-level check (not a text-level one) a
standing gate for any stylesheet change, which the two predicates above deliver
without adding a dependency.
