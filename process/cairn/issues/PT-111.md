### @team-lead — 2026-09-08

Found by the architect on PT-108's gate 4 (2026-09-08): `cairn loop-stats PT-108` attributed 4 full-suite runs to the architect against the cap of 4 when only 2 executed — `loop_stats.classify_bash` classifies a transcript Bash command by its text, so a command the PreToolUse guard refused (un-tiered full run) or one issued from the wrong path counts the same as a run that happened. Fix: cross-check a transcript full-run against `process/cairn/metrics/test-runs.jsonl` (the runner self-records every real run since PT-97) and count only matched runs; unmatched commands get a separate `full_run_blocked` counter so the scorecard still shows the attempt. One regression test with a fixture transcript containing a blocked command and no ledger record. Backlog, not PT-0.12.2 (filed during the drive; Mosko routes new follow-ups).

### @team-lead — 2026-09-08

Feature started. Branch: `feature/pt-111-loop-stats-blocked-runs`.

**Gate 1 brief (architect):** two counters exist in `loop_stats.py`: the scorecard's `full_suite_runs` (~L102-155) is derived from `test-runs.jsonl` records in the window — real runs — while the per-agent audit (`audit_agent`, `classify_bash` ~L199-214, step summary ~L404) counts transcript Bash commands whose TEXT is a full run, so a command the PreToolUse guard refused, or one issued from the wrong path, counts as a run (PT-108: 4 attributed to the architect, 2 executed). Rule on: (1) matching a transcript FULL_SUITE step to a ledger record — by `who` + timestamp proximity (the record's `ts` is the run's end; the transcript step's is its start; runs take 20–140 s) and/or the recorded argv/gate; (2) unmatched steps get their own class (`full_run_blocked`) and counter, shown on the scorecard so the attempt is still visible but never counted against the cap; (3) the hook-blocked case is detectable from the transcript itself (the tool result carries the guard's refusal text) — whether that signal is used in addition to or instead of the ledger match; (4) windows without a ledger (pre-PT-97 loops) keep the old text-only count, labelled. qa: fixture transcript + ledger with one executed run, one guard-refused run (refusal text in the tool result), one wrong-path run; scorecard shows 1 full run + 2 blocked.
