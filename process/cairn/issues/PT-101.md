## Acceptance criteria

Restated by the architect's re-issued gate-1 ruling below (2026-09-08), which supersedes the
earlier value-floor ruling after the builder's measured objection. Every figure is measured there.

1. `token-chart-logic.ts` gains a pure `subPixelColumns(rows, seriesKeys, yMax, plotHeightPx,
   minPx = MIN_BAR_PX)` returning the columns rendering below the floor, each with its true
   `heightPx` and the `topSeriesKey` whose colour the overlay uses. Zero-total columns are
   excluded; a non-positive `yMax` or `plotHeightPx` returns `[]`.
2. `TokenCostChart.svelte` overrides the `marks` snippet with a verbatim copy of layerchart's
   default body plus one overlay layer drawing a `MIN_BAR_PX`-tall rect at the baseline for each
   returned column. **No value change and no domain change** — the y-scale, the stack and the
   tooltip are untouched.
3. The copied marks body is guarded against silent drift: a test pins layerchart's installed
   version and asserts the upstream default body still matches the copied text.
4. The overlay is applied unconditionally — measured empty for ranked's top-12 (12th-largest
   renders at 60.7 px), and a mode branch would miss ranked + "Show all".
5. Plot height is measured through the component's existing observer, not hardcoded from the
   `h-[300px]` class.
6. Lead's browser leg: chronological, both themes, **every** column ≥ 1 px measured before any
   size filter (report the minimum height observed), and the y-axis top plus a floored column's
   tooltip unchanged from PT-102's leg.
7. Full suite green; JS glob green; `dashboard/dist` rebuilt and committed; `cairn check` ok.

### @architect — 2026-09-08

**Gate 1 ruling — PT-101. Decided line (a) is not reachable through layerchart; the floor moves into logic, and the tooltip becomes the honesty condition.**

**Why (a) cannot be done as written, measured in the vendored library.** `Bar.base.svelte` resolves only **style** props per datum — `resolveStyleProp` is applied to `fillOpacity`, `strokeWidth` and `opacity`, and to nothing geometric. `height` is a **scalar** prop, and `Bar.shared.svelte.js:94–96` does `y = y + (height - props.height) / 2` — it re-centres the bar, so a floored bar would float off the baseline. `insets` is scalar too (`insets = props.insets ?? stackInsets`). There is therefore no per-datum hook for rendered geometry, and "a minimum on the rendered height, not on the data" is not expressible through this component's props. Rejected alternative, measured as real but wrong: per-datum `strokeWidth` **does** reach the rect, but the accessor receives only the row — not the `seriesKey` — so it would stroke every segment of the column and straddle the baseline by 0.5 px.

**Seam.** Pure, in `token-chart-logic.ts`, tested in node:
`export const MIN_BAR_PX = 1;` and `export function floorRowForRender(row, seriesKeys, yMax, plotHeightPx, minPx = MIN_BAR_PX)`. Contract: `plotHeightPx <= 0` or `yMax <= 0` → the row is returned **unchanged** (never divide by an unmeasured plot). A summed value of 0 stays 0 (decided line c). Otherwise `minValue = yMax * minPx / plotHeightPx`, and when the row's sum is below it the shortfall is added to the **single largest segment**, every other segment untouched (decided line b), so the segments still sum to the rendered column.

**Apply it unconditionally, not per mode.** Ranked's top-12 cut is measured far above the floor — the 12th-largest issue renders at **60.7 px** (y-max 750,945,497 = PT-84; ~250 px plot; 1 px ≈ 3,003,782 tokens) — so the floor is a no-op there **by construction**. A `chronological`-only branch would be wrong anyway: ranked + "Show all" renders the same 88 bars and hits the same sub-pixel columns.

**The tooltip is the honesty condition, and it is the part that can silently lie.** Once the row handed to the chart carries a floored value, the tooltip formatter — which reads the chart row — would report a false token count for exactly the issues this feature exists to make visible. Rule: add `export function trueTotalFor(payload, issue, metric)` beside the floor, and have the tooltip and any label resolve through it from `tokens.issues`, never from the floored row. This is not optional polish; without it PT-101 trades an invisible bar for a wrong number.

**Plot height must be measured, not assumed.** The component already measures plot **width** through `measureChart` for `tickEveryNth`; extend that same observer to height rather than hardcoding `300 − CHART_PADDING`. A constant would rot silently the day the `h-[300px]` class changes, and the failure mode is a wrong floor with no symptom.

**Measured today: four sub-pixel columns, not the two the issue names** (that pair was PT-88's snapshot; the set grows as issues land): PT-83 **0.712 px**, PT-88 **0.779 px**, PT-95 **0.114 px**, PT-101 **0.632 px**. Pin the visual leg to "every column ≥ 1 px", never to a fixed pair.

**(e) Red tests — qa, `tests/js/token-chart-logic.test.js`.**
1. a row whose total renders below the floor comes back at exactly `minValue` — mutation: drop the `Math.max`.
2. the shortfall lands on the largest segment only, others byte-identical — mutation: distribute it evenly.
3. a zero total stays zero — mutation: floor unconditionally.
4. a row already at or above the floor is returned unchanged — mutation: always add the shortfall.
5. `plotHeightPx = 0` and `yMax = 0` both return the row unchanged and never divide — mutation: remove the guard.
6. `trueTotalFor` returns the payload's total for a floored issue, and the floored row's value differs from it — mutation: read the row instead of the payload. This is the test that proves the tooltip cannot inherit the floor.

**(f) Writers.** qa: `scripts/cairn/tests/js/token-chart-logic.test.js`. implementation-lead: `token-chart-logic.ts`, `TokenCostChart.svelte`, rebuilt `dashboard/dist`. Commit by pathspec; full runs via `run_tests.py --gate <g>`; JS via the canonical glob.

**(g) Visual leg (lead's).** Chronological, both themes. **Every** column ≥ 1 px, measured before any size filter — the PT-88 filter that produced the false 86 is the thing under test here, so count all rects and report the minimum height observed. Second check, equally load-bearing: hover a floored column (PT-95 is the smallest at 0.114 px today) and confirm the tooltip shows its **true** token count, not the floored one.

### @architect — 2026-09-08

**Gate 1 ruling, re-issued whole — PT-101. The decided line is reachable; my earlier value-floor ruling (@3b42f3c) is superseded.** ACs restated in place above.

**What the builder's objection settles, measured.** `BarChart.base.svelte` exposes exactly one layer snippet — `marks`, rendered with `{ context, facet }` — and **no** `children` / `aboveMarks` / `belowMarks`. So an extra render layer is reachable, but only by overriding `marks`, which replaces the default body (33 lines: `context.series.visibleSeries`, per-row `rounded` via `isStackTop`, `radius`, `strokeWidth`, `stackPadding`, an `opacity` accessor keyed on `isHighlighted`, `onBarClick`, `{...props.bars}`, `{...s.props}`). Confirmed again: only style props resolve per datum, `height` is scalar and re-centres (`Bar.shared.svelte.js:94–96`), `insets` is scalar.

**Mechanism: override `marks`, keep the default bars, add a sub-pixel overlay.** Copy the default body verbatim into our snippet so the existing rendering is unchanged, then append one overlay layer drawing a `MIN_BAR_PX`-tall `Rect` at the baseline for each column whose computed height is below the floor. **No value changes and no domain changes** — the y-scale, the stack and the tooltip are untouched by construction.

**Two consequences of the reversal, stated rather than left to be discovered.**
- **`trueTotalFor` is dropped.** I ruled it mandatory an hour ago because a floored *value* would have made the tooltip lie. Under an overlay the data is never floored, so the tooltip is honest with no help and the function has no subject. Do not build it.
- **We now carry a version-pinned copy of library internals.** `layerchart` is `2.3.1` (`^2.3.1` in `package.json`), so a minor bump can change the default marks body under us and our copy would silently diverge — the bars would keep rendering while quietly losing whatever the upstream body gained. This is the real cost of honouring the decided line, and it is paid by test 6 below, not by vigilance.

**Seam — pure, in `token-chart-logic.ts`, tested in node.** `export const MIN_BAR_PX = 1;` and
`export function subPixelColumns(rows, seriesKeys, yMax, plotHeightPx, minPx = MIN_BAR_PX): Array<{ issue: string; heightPx: number; topSeriesKey: string }>`.
Contract: `yMax <= 0` or `plotHeightPx <= 0` → `[]` (never divide by an unmeasured plot); a column whose summed value is `0` is **excluded** (decided line c); every other column whose `sum / yMax * plotHeightPx < minPx` is returned, `topSeriesKey` being the stack-top series with a non-zero value so the overlay takes that column's own colour rather than a fixed one. The component renders one `Rect` per returned column at the band's x and width, `y = <baseline> - minPx`, `height = minPx`.

**Apply it unconditionally, not per mode.** Ranked's top-12 cut is measured far above the floor — the 12th-largest issue renders at **60.7 px** (y-max 750,945,497 = PT-84, ~250 px plot, 1 px ≈ 3,003,782 tokens) — so the overlay yields an empty list there by construction. A `chronological`-only branch would still be wrong: ranked + "Show all" renders the same 88 bars and hits the same columns.

**Plot height must be measured, not assumed** — extend the existing `measureChart` observer that already supplies plot width to `tickEveryNth`. A constant derived from the `h-[300px]` class rots silently the day that class changes, and the failure mode is a wrong floor with no symptom.

**Measured today: four sub-pixel columns, not the two the issue names** (that pair was PT-88's snapshot; the set grows as issues land): PT-83 **0.712 px**, PT-88 **0.779 px**, PT-95 **0.114 px**, PT-101 **0.632 px**.

**(e) Red tests — qa, `tests/js/token-chart-logic.test.js`.**
1. columns below the floor are returned, ones at or above it are not — mutation: drop the comparison so every column is returned.
2. a zero-total column is excluded even though it is below the floor — mutation: include zeros.
3. `yMax = 0` and `plotHeightPx = 0` each return `[]` and never divide — mutation: remove the guard.
4. `topSeriesKey` is the stack-top series **with a non-zero value**, on a row whose last series is zero — mutation: return the last series key unconditionally.
5. `heightPx` is the true sub-pixel height (so the overlay can be audited), not the floored one — mutation: return `minPx`.
6. **Fork guard, the one that pays for the copied body:** assert `layerchart`'s installed version equals the version our copied marks body was taken from, and that the default body in `node_modules/layerchart/dist/components/charts/BarChart/BarChart.base.svelte` still matches the text we copied. Mutation: bump the pinned version constant. Without this the copy drifts silently on the next `npm install`.

**(f) Writers.** qa: `scripts/cairn/tests/js/token-chart-logic.test.js`. implementation-lead: `token-chart-logic.ts`, `TokenCostChart.svelte`, rebuilt `dashboard/dist`. Commit by pathspec; full runs via `run_tests.py --gate <g>`; JS via the canonical glob.

**(g) Visual leg (lead's).** Chronological, both themes. **Every** column ≥ 1 px, measured before any size filter — the filter that produced PT-88's false 86 is the thing under test, so count all rects and report the minimum height observed. Second check: the y-axis top and a floored column's tooltip are **unchanged** from PT-102's leg — that is what distinguishes this mechanism from the one it replaced.
