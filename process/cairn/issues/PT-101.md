Found on PT-88's visual leg (PT-88.md @ cda6770) and framed by the architect at the verdict: in chronological mode every issue is a column (~13 px wide at 1746 px viewport) on a shared scale whose top is ~800 M tokens, so two issues render at 0.489 px and 0.078 px — present in the DOM, invisible to a human, indistinguishable from an issue with no recorded usage. Ask: a minimum rendered bar height of 1 px for any non-zero total (per column, not per role segment), in `TokenCostChart.svelte`/`token-chart-logic.ts`; a JS test that a total of 1 token yields ≥ 1 px; lead's browser leg re-counts visible columns = API issue count with the ≥ 0.5 px filter that produced the false 86 on PT-88. Zero-total issues stay at zero height by design.
