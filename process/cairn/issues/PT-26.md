New capability: an issue can declare other issues as blocking it. No
`blocked-by`/`depends` support exists anywhere in engine, board, or spec today.

Design points for the architect at start-feature (settle before implementation):
field name (`blocked-by` proposed), list-valued frontmatter semantics (precedent:
`labels`), and whether blocking is purely informational or the board/CLI warns
when a blocked issue moves to in-progress.

## Acceptance criteria

- [ ] Schema: a list-valued blocking field on issues, default `[]`; TRACKER.md frontmatter table + a worked example updated.
- [ ] `cairn check` lints: dangling reference, self-reference, and dependency cycles all reported as errors.
- [ ] CLI: `cairn new` and `cairn set` can write the field (set/clear); `cairn show` displays blockers and, ideally, reverse ("blocks") links.
- [ ] Board: card chip and/or drawer surfaces blockers, distinguishing open blockers from resolved (done/cancelled) ones.
- [ ] The ruled informational-vs-warning behavior is implemented and recorded in TRACKER.md.
- [ ] Test-first: pytest for engine/lint/CLI, node:test via board-logic.js for board logic.
