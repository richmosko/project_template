## Embed strategy ruling

Investigated first: read `board.js` (2,517 lines), `board-logic.js`, `board.css`
(875), `board.html`, and probed the running server. Measurements below are from
this branch's HEAD, not recalled.

### Verdict: **(a) same-origin iframe at `/?embed=1`.** Decisively, not on balance.

Options (b) and (c) are not close, and the reason isn't taste — it's three
measured properties of the vanilla board.

**1. `board.js` binds to a DOM contract it does not own.** ~30 hard
`document.getElementById(...)` calls against ids that live in `board.html`
(`main`, `drawer`, `drawer-overlay`, `toast`, `pull-indicator`,
`connection-state`, `engine-stale-banner`, `majors-tabs`, `tab-kanban`,
`tab-list`, `filter-*` ×7, `new-issue-*` ×6, `expand-all-btn`,
`collapse-all-btn`). Option (b) — script-tag the vanilla files into the Svelte
page — means reproducing that entire markup contract inside a Svelte component
and keeping the two in lockstep forever. Every id typo is a null-deref at init,
and nothing in either file names the contract.

**2. Entry and view-mode are both page-level, not component-level.**
`document.addEventListener("DOMContentLoaded", init)` never fires for a script
injected into an already-loaded SPA, and — the sharper one —
`var isListView = window.location.pathname === "/list"` (board.js:129). The board
reads its view mode **from the page URL**. Under (b), the embedded board is
permanently kanban, and AC2's Kanban⇄List toggle can only be met by editing
board.js's view-mode source. That edit is the camel's nose: it is the first of
the "small changes" that turn reuse into a fork.

**3. `board.css` and the shadcn token namespace collide — measured.**
`board.css`'s `:root` defines 11 custom properties; **three of them —
`--accent`, `--border`, `--radius` — are also shadcn token names** used by every
component in the dashboard app. It also sets `* { box-sizing }` and a `body`
rule (background, font-family, font-size, `overscroll-behavior-y`). Load that
stylesheet into the dashboard document and whichever `:root` wins silently
repaints every shadcn border and corner radius in Atlassian values. Scoping it
would mean rewriting 875 lines of CSS — a fork of the stylesheet to avoid a fork
of the JS.

**The iframe makes all three structurally impossible rather than carefully
avoided:** its own document, its own `:root`, its own `DOMContentLoaded`, its own
`location.pathname`. And it is *maximal* reuse — literally the same files, the
same `/api/board` fetch, the same PT-36 column list. AC1's "no second fetch
layer, no duplicated column list" isn't a discipline we maintain here; it's a
thing that cannot happen.

**(c) a Svelte board component is rejected.** It is a fork of 2,517 lines of
logic plus a second consumer of `/api/board`, and it contradicts this issue's
stated constraint. I'm not superseding that constraint: the migration to real
shadcn components is PT-57's job, done once, for both surfaces — not smuggled in
here as an "embed."

Verified there's nothing to fight: the server sets no `X-Frame-Options` and no
CSP, and `/?embed=1` and `/list?embed=1` both return board.html 200 (the query
string is already stripped by `urlparse` before routing).

### AC2 comes free — do not build a Svelte toggle

The board's own view tabs are `<a href="/">` / `<a href="/list">`. Inside a frame
those navigate **the frame**, same-origin, no target needed. So Kanban⇄List works
inside the dashboard with **zero new code**, and lane collapse likewise (it's
board.js state, PT-30-persisted). Building a Svelte segmented control that drives
`iframe.src` would be new, untested code duplicating a control that already
works.

Consequence to accept knowingly: the parent doesn't know which view the frame is
showing, and a dashboard reload resets it — except that PT-30's view state is
`localStorage`-backed on the same origin, so in practice the frame and the
top-level board **share** view/lane state. That's coherent, not a bug. Don't
"fix" it.

### `embed=1` scope: suppress exactly two things

Not "the header chrome" broadly — the filters, majors tabs, expand/collapse, and
`+ New` are all board function, and the dashboard has no replacement for them.
Hide only:

1. the `cairn` wordmark (the dashboard page already has a title), and
2. **the `/dashboard` tab** — which I added in PT-54, and which inside the frame
   is now an actual bug: clicking it loads the whole dashboard SPA *inside the
   dashboard's own board panel*. This is the one thing the param must fix.

Implementation shape: put the param read in **`board-logic.js` as a pure
function** (`isEmbedMode(search)`), exported on `CairnLogic` per that file's
existing contract, so it's unit-testable in the node harness that already exists;
`board.js` calls it once in `init` and toggles a `body.embed` class; `board.css`
gets one rule block under `body.embed`. That's roughly 8 lines across three
files, all additive — no existing behaviour re-routed.

### Interaction scope: **full read-write, inherited — not implemented**

Drag, drawer, inline edits, `+ New` all work inside the frame with no code at
all, because it is the board. Making the dashboard copy read-only would require
inventing a read-only *mode* in board.js — a new state, new branches, new tests —
in a file this issue says not to fork, to deliver *less* function. Ruled: full
interaction, and the AC's "ruled, not accidental" is satisfied by this paragraph.

Two contained consequences, both fine: the drawer and toast are `position: fixed`
and therefore fix to the **frame's** viewport, rendering inside the board panel
rather than over the whole dashboard; and a mutation inside the frame refreshes
the frame's own board via its own SSE, while the dashboard's status cards refresh
on their own SSE + 15s poll (PT-54). Two independent freshness paths over the same
data — no coordination needed, none should be added.

### Visual coexistence: **honest seam. No token bridge.**

The document boundary already guarantees the two palettes can't contaminate each
other (see collision measurement above) — so the only question is presentation.
Frame the board panel as what it is: a shadcn `Card` with a real header
("Board" + an "Open full board" link), the iframe filling the content area with a
`rounded-md border`, and one plain line of copy noting the board keeps its legacy
styling until PT-57. A seam a user can see and understand costs less than a seam
they can't.

**Explicitly rejected: injecting an override stylesheet into the frame to
re-point board.css's 11 vars at shadcn values.** It would need the palette values
duplicated into a second file inside the frame — a second source of truth for
tokens, which is exactly what `tokens.css` exists to prevent — or a postMessage
handshake to pass computed values across. And mapping Atlassian roles onto
shadcn roles ad hoc pre-empts PT-57 with an untracked partial migration that is
neither palette. Half-migrated is worse than legacy-and-labelled.

### Container geometry: fixed height, no auto-height protocol

Give the frame a viewport-relative height (`h-[70vh]` is a reasonable start;
tune visually). **Do not** build a postMessage auto-height protocol: the board is
a full-height app that owns its own scrolling — sticky header, horizontally
scrolling column strip, `position: fixed` drawer/toast/pull-indicator. Auto-height
would produce an ever-growing page *and* break the sticky/fixed chrome that
assumes a bounded viewport.

Also: **no `sandbox` attribute** (it's our own same-origin code and sandboxing
would break storage and same-origin access), **do** set a `title` for
screen-reader traversal, and skip `loading="lazy"` — deterministic beats a
marginal saved connection.

### Accepted costs, named

- **A second full board bootstrap per dashboard tab** — one extra `/api/board`
  fetch and one extra `EventSource`, so a user with both surfaces open holds
  three SSE connections (one thread each on the threading server). Bounded and
  fine for a single-user localhost tool; it is not a pattern for anything
  multi-client.
- **Focus and screen-reader traversal cross a document boundary.** Real, and the
  `title` attribute is the mitigation, not a fix.
- **The seam is temporary by design.** When PT-57 migrates the board to
  shadcn-svelte, the frame stops being the only honest option and this becomes a
  component-embed decision to revisit. That's a feature of this ruling: it buys
  time without spending PT-57's budget.

### Test shape (qa-engineer)

- `isEmbedMode(search)` in the existing node harness: `?embed=1` on, absent/empty/
  `embed=0`/garbage off (same "only the exact spelling counts" posture as PT-42's
  `archived=1`).
- Python: `/?embed=1` and `/list?embed=1` both 200 and serve board.html — pin that
  the query param never reaches routing.
- DOM-level: with `body.embed`, the wordmark and `#tab-dashboard` are not
  displayed, while `#filter-text`, `#majors-tabs`, `#new-issue-btn` and
  `#tab-kanban`/`#tab-list` still are. Assert on computed visibility, not on the
  class being present — the class is the mechanism, the hiding is the claim.
- The dashboard page renders exactly one `<iframe>` whose `src` resolves to a 200.
- **Not** worth testing: that the board renders inside the frame. It's the same
  board, covered by 331 existing JS tests.

requirement, not speculatively against a hypothetical one. Recording it as a
known consequence so it can't arrive as a surprise.

### @architect — 2026-08-27

### Two rulings for qa-engineer (sandbox globals; DOM-assertion shape)

Both were investigated against the tree at `5756f58` + current working tree, not
reasoned from the descriptions.

#### 1. `URLSearchParams` in the vm sandbox → **(b): board-logic.js stays pure ECMAScript. Do not extend `loadCairnLogic`.**

The report is accurate — confirmed independently: in a fresh `vm.runInNewContext`
sandbox both `URLSearchParams` **and** `URL` are `undefined` (only ECMAScript
intrinsics like `JSON` are present). Good catch, and exactly the right thing to
escalate rather than route around.

Ruling is (b), and the reason is stronger than "convention":

`helpers.js` has already paid for cross-realm hygiene **three separate times** —
PT-29 (data exports wrapped into functions), PT-30 (null-prototype maps lost
through a JSON round-trip), PT-31 (`__proto__`-named keys silently dropped) —
and `rehome()`'s stated precondition is that *every* `CairnLogic` function
returns plain JSON-shaped data, "no Dates/Maps/RegExps that a structural copy
can't reproduce." Injecting a **host-realm** constructor into the sandbox is the
mirror image of the class those three fixes closed. For `isEmbedMode` specifically
nothing would cross the boundary (it returns a boolean) — but the *precedent*
is what I'm ruling on: once the harness supplies Web globals on demand, it must
chase the browser's global surface forever (`URL` next, then `fetch`, then
`localStorage`), and the first such function that returns a `URL` or a `Map`
breaks `rehome`'s invariant quietly. The bare sandbox being a **sufficient**
environment is what makes these tests trustworthy; that's the property worth
protecting, not the line count.

There's also a behavioural argument that happens to favour (b), which I checked
rather than assumed: `new URLSearchParams("%65mbed=1").get("embed")` returns
`"1"` — percent-decoded keys match. My ruling was "only the exact spelling
counts" (the PT-42 `archived=1` posture), and `?%65mbed=1` is not that spelling.
Hand-rolled matching is *more* faithful to the requirement, not a downgrade from
it.

**Semantics, ruled explicitly so nobody has to infer them:** strip one leading
`?`; split on `&`; compare the key **case-sensitively** against `embed`; on the
**first** `embed` key found, on iff the value is exactly `1`. First-wins on
duplicates — matching both `URLSearchParams.get` and the python side's
`parse_qs(...)[0]` posture, so the two languages can't disagree. A bare `embed`
with no `=` is off.

**Status in the tree right now** (verified this turn, not from report): the WIP
`board-logic.js` already implements exactly this, hand-rolled, and **all 8 of
qa's committed tests in `embed-mode.test.js` pass against it.** So this ruling
ratifies where the code already is; its job is to stop a later "cleanup" from
reintroducing `URLSearchParams` and re-opening the harness question. No change to
`helpers.js`, no rewrite of the 8 tests.

#### 2. DOM-level assertions → **adopt option 3 (both legs), with the automated leg made non-theatrical.**

First, my error, plainly: I prescribed "assert on computed visibility, not on the
class being present" without verifying the harness could express it. It can't —
no jsdom, no `document`, no computed styles, and eight existing test files
already document that limitation. Prescribing an assertion form the harness
can't produce is the failure mode I've been bitten by before; qa was right to
stop and ask rather than write around it.

**Automated leg — source-text guard, but it must assert *agreement*, not
existence.** "A rule exists" and "a class is added" are each individually
worthless; the realistic regression is the two drifting apart. So:

1. Extract the class token `board.js` adds under embed mode and the token
   `board.css` hides under, and assert they are **the same string**. A rename in
   one file must fail this test.
2. Assert the set of selectors hidden under that class is **exactly** the two
   ruled elements — the wordmark and `#tab-dashboard`. A later broad
   `body.embed .app-header { display: none }` must fail. This pins the *ruling*,
   not just the mechanism.
3. Assert `#tab-kanban`, `#tab-list`, `#filter-text`, `#majors-tabs`,
   `#new-issue-btn` are **not** among the hidden selectors — AC2 depends on the
   view tabs surviving.

That is a real invariant a source guard can prove. Use the existing
`extractFunctionBody`-style helpers; don't invent a second convention.

**iframe attributes — convert the part that can be behavioural.** Read the
`<iframe>` from the component source as text (exactly one; has `title`; has no
`sandbox`), then take its `src` **literal** and feed it to the live server in the
python harness, asserting 200. The attribute claims stay source-text; the "does
this URL actually resolve" claim becomes a real request.

Add one more cheap check while you're there: assert the committed
`dist/assets/index.js` contains that same `src` literal. That's the PT-54 §3
committed-dist staleness risk (PT-58 is the general fix) caught for this feature
specifically, for one line.

**Manual leg — one Validate-phase browser pass, recorded.** team-lead drives
claude-in-chrome: confirm the two suppressed elements are genuinely not visible
using `elementFromPoint`/screenshot — **never property or class reads** (PT-32's
scar: occlusion produced a whole section of false positives) — and confirm the
board renders inside the frame with its own tabs navigating the frame. One-time
before merge, not per-run. **Post the result as a comment on this issue**: a
manual check nobody records is a check that didn't happen.

Net: option 3 as qa proposed, with leg 1 tightened from "the code says the right
thing" to "the two files agree and the ruling's scope is pinned."

guard whose extractor is unverified proves nothing; these are verified.

The two-independent-extractions design (JS token from `init`'s body, CSS token
from the first `body.<word>` rule, then asserted equal) is exactly the agreement
property I asked for, and the "these five selectors are NOT hidden" test pins

The `sandbox` correction landed correctly: the python guard extracts the

With team-lead's browser pass on record (`6adae13`), the automated gate is doing
the job it should — guarding regressions, not proving rendering. Nothing further
required from qa on this feature.

#### 3. Persistence fix (`embedAwareHref`) — approved, with one backstop and one nit

**Fix location is right.** Rewriting the two static hrefs once in `init` — rather
than per-render in `renderHeader`, which only ever toggles `className` — matches

**Backstop (recommended, one line, already flagged to team-lead).** Href
rewriting is *enumerative* — it must cover every navigating link, forever — and
the failure the browser pass caught was exactly "a navigation source didn't carry
the param," silently. The hazard is inherent to being framed, not to the query
param, so:

```js
var isEmbedMode = CairnLogic.isEmbedMode(window.location.search) || window.self !== window.top;
```

A future missed propagation then degrades to "still embed-styled" instead of
"recursion hazard returns." Stated cost: the backstop hides the bug it protects
against — URL and styling can silently diverge. Nothing keys off the param, so
that divergence is inert, and I'd take that trade over the hazard reaching a user.
team-lead's call; not a blocker either way.

**Nit — `embedAwareHref`'s unguarded `?`.** Verified: `embedAwearHref("/list?foo=1",
true)` returns `/list?foo=1?embed=1`. Both current callers pass bare paths so
nothing is broken today, but the function is exported and reads general. Either
document the precondition in its comment ("`path` must carry no query string") or
make it one line more honest:

```js
return embedOn ? path + (path.indexOf("?") === -1 ? "?" : "&") + "embed=1" : path;
```

I'd take the second — it costs one line and removes a trap that only surfaces
when someone reuses the helper.

#### On the manual leg

Worth recording plainly: the Validate browser pass found, on its first run, a
real defect that no automated gate in this repo could have caught — the embed
param not surviving in-frame navigation. That is the argument for keeping a
manual confirmation in the loop for anything whose claim is "a user sees X,"
and it is now evidence rather than assertion.
