## Problem

Found by Mosko on the merged PT-88 (2026-09-08): chronological mode orders issues by id, which is the order they were *opened*, and the caption says so. The question it was built to answer — is per-issue usage creeping up over *time* — is about when the tokens were *spent*, and the two orders diverge whenever an issue waits in the backlog. Measured from `process/cairn/metrics/token-usage.jsonl` (`window_start` per record):

| Issue | Opened (`created:`) | Tokens spent |
|---|---|---|
| PT-88 | 2026-09-04 | 2026-09-08 |
| PT-93 | 2026-09-05 | 2026-09-06 |
| PT-95 | 2026-09-05 | 2026-09-06 |
| PT-99 | 2026-09-07 | 2026-09-08 |

So today's work (PT-88) renders between last week's PT-87 and PT-89. PT-88's issue premise ("id order is chronological order") holds for filing, not for work. `GET /api/tokens` per-issue payload carries only `issue, kind, roles, total` — the chart has nothing else to order by.

## Ask

1. `GET /api/tokens` adds per-issue `first_active` / `last_active` (ISO date, min/max `window_start`/`window_end` over that issue's records, both sources); milestone/main buckets may carry them too but chronological mode still omits those bars (PT-88 ruling).
2. Chronological mode orders by `first_active` ascending, tie-break by id; issues with no records keep id order at the end, or are omitted — architect's call, stated.
3. Caption: "Showing all N issues in the order worked" (replacing "in the order opened"); the Ranked caption unchanged.
4. Unit tests: ordering by `first_active` with an id tie-break; the divergence fixture above (PT-88 after PT-99); the caption string; a Python test that the endpoint's `first_active` equals the min `window_start` over a fixture file.

## Acceptance criteria

1. With the live data, PT-88 renders to the right of PT-99 and PT-83 in chronological mode; the ticks are no longer id-sorted.
2. Lead's browser leg: both themes, chronological only (ranked unchanged), leftmost bar = the issue with the earliest `first_active` by tooltip, count every column before filtering by size (PT-88 lesson).
3. Full suite green via `run_tests.py --gate finish`; JS glob green; `dashboard/dist` rebuilt and committed; `cairn check` ok.

Out of scope: a true time axis with idle-day gaps (not worth it at this corpus size).
