## Problem

Split from PT-96's gate-1 ruling (2026-09-06). PT-96 removes the `serve_forever` poll-interval
cost — serial 176.6 s → 109.6 s, parallel 26.4 s → 19.9 s. Two files stay above the 8 s ceiling
afterwards, and neither yields to fixture work. Consolidation was measured and is not a speed
lever. Data: `process/reviews/PT-96/timings.md`.

## Ask

1. `test_otel_receiver_self_stop.py` — 18.64 s, the suite's floor at any worker count. Twelve
   tests ≥ 0.5 s sum to 18.92 s of real daemon waiting. The grace period is already shrunk
   (`GRACE = 0.4`); what remains is deliberate slack — `sleep(GRACE + 1.0)`,
   `sleep(PERIODIC_REAP * 6)`. Cutting it trades wall time against flake risk on the daemon's
   own timing contract, so it needs a flake budget and repeat runs, not a quick edit.
2. `test_backfill_tokens.py` — 11.27 s, 40 tests each spawning `python3 backfill_tokens.py`
   (~0.28 s median). Calling `main()` in-process would delete the CLI boundary these tests
   exist to cover. If it converts, the CLI boundary needs its own smaller set of subprocess
   tests, not silent removal.
3. **Consolidation**, carried over from PT-96 ask 2 on hygiene grounds only: merge per-feature
   sliver files (2–5 tests on one subject) by subject; retire tests whose subjects were retired
   (PT-85's ramp guard is one). Measured cost of a file is ~0.03 s of interpreter start, and
   merging coarsens the parallel packing — do this for readability, and expect no speed-up.

## Acceptance criteria

Amended by the lead (AC1's 10x battery withdrawn) and by the architect's gate-1 ruling below
(2026-09-08); every figure there is measured at 398ee14.

1. Each converted test names the mutation that turns it red, and the loop ends with **one**
   confirming `run_tests.py --gate verdict`. No repeat-run batteries.
1a. Only *positive* waits convert to polling; the two negative waits (`sleep(GRACE + 1.0)` at
   L687 and L729, asserting the daemon has **not** exited) keep their wall-clock duration, and
   the `+ 1.0` margin is not re-expressed as a multiple of `GRACE`.
1b. The retained subprocess set in `test_backfill_tokens.py` covers **every** distinct argv shape
   the converted tests used; qa enumerates those shapes on this issue.
1c. The target is honest, not the 8 s ceiling: `test_otel_receiver_self_stop.py` ~16.4 s and
   `test_backfill_tokens.py` ~9.8 s. Neither reaches 8 s and nothing in scope makes them.
2. Any test deleted has a comment here naming the retired rule and why it is no longer true.
3. Before/after per file appended to `process/reviews/PT-96/timings.md`; `cairn check` ok.

### @architect — 2026-09-08

**Gate 1 ruling — PT-98. Neither file reaches the 8 s ceiling in this scope, and the ruling says so up front rather than at the verdict.**

**Measured at 398ee14** (`run_tests.py -p … --json`, narrowed so no full run is spent on a ruling): `test_otel_receiver_self_stop.py` **18.94 s**, `test_backfill_tokens.py` **11.70 s**.

**(a) The rule that decides which wait converts: positive assertions poll, negative assertions wait.** A test asserting *"X happens"* can poll for X's observable effect with the same deadline and return early. A test asserting *"X has **not** happened by T"* has no signal to poll — the wall-clock wait **is** the assertion, and shortening it shortens the claim.
- **Convert — `time.sleep(self.PERIODIC_REAP * 6)` (L1435, 3.0 s).** Positive: it waits for a periodic reap to have occurred. Replace with a poll for the reap's observable effect, deadline `PERIODIC_REAP * 6` — same worst case, typical return after one reap. Expected saving **~2.0–2.5 s**.
- **Keep — `sleep(self.GRACE + 1.0)` (L687) and `sleep(grace + 1.0)` (L729), 1.4 s each.** Both assert the daemon has *not* exited. These are the contract.
- **Keep — `grace * 0.3` (L723, 0.12 s)** and the `0.1`/`0.05` poll intervals inside `_wait_for_*`, which are already deterministic.
- **Do not re-express the `+ 1.0` margin as a multiple of `GRACE`.** It absorbs scheduler jitter, which is absolute, not proportional, and the suite runs 8-way parallel — a 0.4 s margin would not survive a 0.5 s scheduling hiccup. *(reasoned from the parallel context, **unmeasured** — I did not measure jitter under load; treat as a floor on the margin, not a licence to raise it.)*
- **Free strengthening at zero wall cost, optional:** poll `--status` *throughout* each negative window and fail on the first non-running observation, instead of a single check at the end. Same duration, catches an early exit anywhere in the window rather than only at its edge.

**(b) The subprocess cost is a third of the file, not all of it.** Measured spawn+import floor for `backfill_tokens.py`: **0.076 s** per invocation → **3.05 s of the 11.70 s**. The remaining ~8.6 s is the script's real work and **survives conversion unchanged** — calling `main()` in-process saves interpreter start and import, nothing more. Converting ~25 of the 40 tests therefore buys **~1.9 s**, not the ~7 s a naive "0.29 s × 25" would suggest.
**The boundary set is defined by argv-shape coverage, not by a count.** qa enumerates the distinct argv shapes the converted tests used and lists them on this issue; the retained subprocess tests must cover **every** shape in that list. A conversion that drops a shape is a silent deletion of CLI coverage, which is exactly what ask 2 forbids.

**(c) Consolidation — hygiene, and narrower than it looks.** Measured: **19 of 88 files have ≤ 5 tests**. At ~0.03 s of interpreter start per file, merging all 19 into six would save **~0.4 s** and coarsen parallel packing, so this is readability work with no speed claim attached.
- Merge only where the subject is *clearly* shared. The two ratified-text scanners — `test_gate_leg_naming.py` and `test_js_runner_canonical_form.py` — are one subject and the clean case.
- **Do not merge a file whose subject was touched in the last three loops** (`test_dashboard_chart_ramp.py`, `test_gate_leg_naming.py`'s counterpart in PT-99, PT-101's and PT-102's files): folding a guard that landed days ago into a larger module loses its reviewable history for no measured gain.
- **The retirement the Ask names is already done.** PT-85's ordinal `--chart-flow-*` ramp guard was retired by **PT-83** — `check_ordinal_ramp` was never built and `test_chart_variant_ramps.py` was deleted there. `test_dashboard_chart_ramp.py`'s five surviving tests guard PT-92's *categorical* tokens and are live. Do not delete them hunting a retirement that has already happened. Any other retirement is named on this issue with the rule and why it stopped being true (AC2, unchanged).

**(d) The honest target.** `test_otel_receiver_self_stop.py` **18.94 → ~16.4 s**; `test_backfill_tokens.py` **11.70 → ~9.8 s**. **Neither reaches 8 s**, and no work in this issue's scope makes them. The floor is set by 49 `run_fake_receiver` spawns (≥ **4.2 s** at the measured 0.086 s floor) plus daemon-startup polling in the first file, and by the script's own work in the second. `self_stop` therefore remains the suite's parallel floor. Suite wall at default jobs: **~19.9 s → ~18 s** *(projected from the per-file deltas, **unmeasured** until built — the verdict measures it)*.

**(e) Writers.** qa: the test modules. implementation-lead: nothing unless a polling helper is added to `tests/helpers.py`, in which case that file is theirs. **AC1 as amended:** each converted test names its red mutation; **one** confirming `run_tests.py --gate verdict` at the end. No batteries. **(f) No browser leg.**
