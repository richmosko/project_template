### @seceng — 2026-08-20

Found during PT-4 Validate code-path review (2026-08-20). board.js:567 (pre-existing, untouched by PT-4) builds the PR link via raw string concatenation into innerHTML:

    prP.innerHTML = 'PR: <a href="' + issue.pr + '" ...>' + issue.pr + "</a>";

`pr:` is free-text nullable frontmatter with no server-side format validation (confirmed against cairn.py). Under the ratified threat model (issue files are hand-editable = untrusted), this is a live executable injection point: a hand-edited pr value like `"><img src=x onerror=...>` breaks out of the href attribute and inserts a real element whose onerror fires (innerHTML-inserted <img onerror> executes, unlike <script>). A `javascript:` URI in pr: is a second, click-gated variant.

Fix: build the anchor via createElement/setAttribute + textContent (no HTML assembly is justified here — there's no markdown in this field), which closes both variants. Same class of fix PT-4 applied to the description/comment sinks.

Also fold in (RECORDED, same area): vendor/NOTICE.md's re-vendoring instructions trust an unauthenticated curl-by-eye; add a sha256 checksum step verified against the npm tarball.
