Mosko (2026-09-08): "Dashboard header should be fixed to top and not scroll."

**Where:** the shell header in `scripts/cairn/dashboard/src/App.svelte` (`<header class="flex flex-wrap items-center justify-between gap-4">`, ~L333) — the Sidebar.Trigger + "Project Dashboard" title/subtitle on the left, the theme/settings cluster on the right. It renders before the route switch, so it is shared chrome on both the Dashboard and Issue Tracking pages. Today it sits inside the `min-h-screen` flex column under `Sidebar.Inset` and scrolls away with the content.

**Acceptance criteria**

1. On both routes (`/dashboard`, `/dashboard/board` or whatever the Issue Tracking route is), scrolling the page content keeps the header at the top of the viewport: after scrolling to the bottom, the header's bounding rect still has `top` ≈ 0 and the title is `elementFromPoint`-visible (not just `position` reads — PT-32/PT-88 rule).
2. Content is not hidden under it: the first card's top edge is fully visible at scroll 0 (no overlap; a spacer or padding equal to the header height), and the page has no horizontal scrollbar at 1280 px and 768 px widths.
3. The header keeps the card canvas convention (opaque `--muted`/`--background` surface with the design system's border or shadow token so scrolled content does not bleed through), in light and dark, in two variants — browser-verified by the lead, screenshots on the issue.
4. The sidebar (`Sidebar.Provider`/`Sidebar.Inset`) still opens/collapses correctly with the header fixed; the Sidebar.Trigger remains inside the header and reachable.
5. The embedded board iframe on the Dashboard page (fixed height, owns its own scrolling) is unaffected; the standalone `/board` + `/list` zero-build fallback is out of scope.
6. `dist/` rebuilt and committed by implementation-lead; `check_dist_freshness.py` rc 0; a source scan test pins the header's positioning classes (sticky/fixed + top-0 + z-index token) so a later layout pass cannot silently drop them.

**Notes for the ruling:** `sticky top-0` on the header inside the existing flex column is the smallest change if the scroll container is the document; if `Sidebar.Inset` owns the scrolling, the header may need to move outside the scroll container instead — the architect decides which, and whether the subtitle line collapses at narrow widths.
