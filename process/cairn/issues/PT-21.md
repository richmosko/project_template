Found by qa-engineer while designing PT-2's numeric-vs-lexicographic id-sort test (2026-08-20). cmd_ls iterates _dir_glob's result directly with no re-sort, so output order is lexicographic-by-filename, not numeric-by-id. Once a tracker has both single- and double-digit issue numbers (this one does: PT-1..PT-21), `cairn ls` prints PT-10..PT-19 before PT-2..PT-9. Live, reproducible today.

Pre-existing, out of PT-2's scope. PT-2 adds its own correct numeric grouping/sort in the snapshot renderer; this ticket is to bring the same numeric-by-id sort to cmd_ls. Likely a shared id-sort key helper both paths can use. P3 — display-order only, no data risk.
