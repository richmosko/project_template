## Problem

Three related gaps (Mosko, 2026-08-23):
1. No first-class way to mark a Milestone or Major "Done" — today the lead hand-edits `status: completed` in the file on a branch.
2. Status vocabulary is split: issues use `done`, milestones/majors use `completed`. Should unify on the issue cycle's `done`.
3. No archive mechanism for done Milestones/Majors — `cairn archive` covers issues only; completed milestone/major files accumulate in the live directories forever.

## Acceptance criteria

- [ ] Architect design ruling first: status-value migration (completed→done — a named `cairn migrate` per the PT-28 precedent, incl. check_repo lint update and downstream-repo posture), CLI surface (`cairn set` on milestones/majors? a dedicated command?), archive semantics (what happens to issues referencing an archived milestone — dangling-ref lint interaction)
- [ ] Marking done is one command; lint accepts only the unified vocabulary
- [ ] `cairn archive` (or sibling) moves done milestones/majors with referential integrity preserved
- [ ] This repo's own live data migrated in the same PR (`cairn migrate lifecycle-status` run against process/cairn/ — 1 major + 8 milestones carry old vocabulary); `cairn check` green at HEAD when the PR merges
- [ ] Skill write-paths emit the new vocabulary (setup-tracker:57, merge-pr:45, merge-pr:61 — temp/2026-08-23-architect-skill-write-path-drift.md §B)
