### @implementation-lead — 2026-08-27

Implemented per team-lead's git-aware steer (overriding the issue's original
"mtime vs mtime" framing):

- New standalone script `scripts/cairn/check_dist_freshness.py`, sibling of
  `cairn.py` (not a `cairn` subcommand — dashboard-specific, not tracker
  functionality). Exports `check_dist_freshness(repo_root: Path) -> dict`
  (`{"stale", "reason", "message"}`) plus a CLI entry point.
- Compares the latest COMMIT touching dashboard source (`src/`, `index.html`,
  `package.json`/`package-lock.json`, `vite.config.*`, `svelte.config.*`,
  `tsconfig*.json`, `components.json`, `public/`) against the latest commit
  touching `dist/`, by commit timestamp — never raw mtime, since a
  clone/checkout resets mtimes arbitrarily.
- Reasons: `fresh`, `stale`, `dist-never-built` (dist/ never committed at
  all — distinct fix from "rebuild"), `uncommitted-src-changes` (honest
  limitation: can't know if an uncommitted edit is reflected in committed
  dist/, and `/finish-feature` runs pre-PR), `no-dashboard` / `git-unavailable`
  (never-raise degrade path, matching `read_git_tags`/`read_git_state`'s
  convention). A doc-only commit touching neither src nor dist never flips a
  fresh repo to stale — falls out of the "compare latest touching commits"
  design with no special-casing.
- Added as gate #3 in `.claude/skills/finish-feature/SKILL.md`, before the
  "no uncommitted changes" check — hard-fails `/finish-feature` with a clear
  message when dist is stale or has uncommitted source changes.
