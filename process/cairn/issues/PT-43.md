## Problem

Found by Mosko immediately after the first `cairn archive` run (2026-08-23): the milestone progress strip computes its `n/m done` counts from `issues/` only, so every milestone whose done issues were swept to `archive/` now reads `0/0 done` (e.g. PT-0.4 · v0.4.0 · 0/0 done — it shipped 13). PT-0.6.2 still reads 3/3 only because its issues closed after the sweep cutoff; the next sweep zeroes it too. Archival must not erase a completed milestone's record from the strip.

## Acceptance criteria

- [ ] Architect design ruling first: count archive/ into the strip's tally (payload/perf posture for old repos), vs render completed milestones differently (e.g. "✓ shipped" instead of a count), vs both — and alignment with PT-42's Show-Archived server surface so archive/ isn't read two different ways
- [ ] A completed, fully-archived milestone never displays 0/0
- [ ] Counts remain correct for the mixed case (some issues archived, some live)
