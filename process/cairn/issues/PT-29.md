## Problem

Three board-UX gaps, all in the swimlane rendering (`scripts/cairn/board/`), requested by Mosko 2026-08-22:

1. **No default roll-up.** Every milestone lane loads expanded; a populated board opens as a wall of issue cards. The lanes should load **collapsed** (issues hidden), letting the user disclose the milestones they care about. Collapse state stays view-local/in-memory per the PT-16 contract — only the *default* flips.
2. **The disclosure toggle reads as a dot.** PT-16's toggle already uses `▾`/`▸` glyphs (`board.js` ~L444/487), but `.swimlane-toggle` has `font: inherit` at lane-header size — the glyph renders too small to read as a triangle. Replace with **filled, legibly-sized triangles: down `▼` = shown, right `▶` = hidden** (size via CSS, not just a bigger glyph in inherited font).
3. **No containment boundary.** Majors/milestones are flat header rows above loose issue-card grids. Render each shown major/milestone as a **larger containing card** — a bordered/surfaced card the issue cards sit *inside* — so the hierarchy is visible as nesting, not just headings. Applies to both grouping modes (milestone lanes, and repo→milestone nesting from PT-3 multi-root).

## Acceptance criteria

- [ ] On load, all milestone lanes are collapsed by default (issues hidden); expanding is one click and stays view-local (no disk write, no network call on toggle — PT-16 contract preserved)
- [ ] Disclosure token is a filled down triangle (▼) when expanded and filled right triangle (▶) when collapsed, sized to be legible at a glance; aria-labels preserved
- [ ] Each shown major/milestone renders as a containing card with the issue cards visually embedded inside its boundary, in both single-root and multi-root (repo-grouped) modes
- [ ] Repo-scoped keys preserved (bare-id-across-roots defect class — zero regressions); drag-and-drop and the drawer still work inside the new containment structure
- [ ] Pure-logic changes covered by the board-logic.js node:test suite (red-first); DOM/visual behavior verified via team-lead Chrome pass against a QA-authored checklist
