## Problem

`test_dashboard_chart_ramp.py` guards PT-61's ordinal `--chart-flow-*` ramp with the dataviz
skill's external `validate_palette.py`. On a harness without it the three validator tests skip,
and a skip is indistinguishable from a pass in a green run. That ramp is the palette that once
shipped two sub-floor values. PT-79 vendored a stdlib categorical validator
(`scripts/cairn/tests/palette_check.py`) for the role palette precisely so its guard never skips;
the ordinal ramp is now the only chart palette still unguarded here.

## Ruling (architect, 2026-09-04, PT-79 review)

Vendor the ordinal check the same way: extend `palette_check.py` with `check_ordinal_ramp(css_text)`
implementing the four checks the spec (design-system-spec.md, validator evidence at ~line 173)
records — monotone lightness, adjacent ΔL ≥ 0.06, hue spread ≤ 40°, light-end contrast ≥ 2:1
against each mode's real `--card`, both surfaces parsed from the CSS under test. Thresholds are the
spec's, not the module's.

## Acceptance criteria

1. `test_dashboard_chart_ramp.py` runs the ordinal checks through `palette_check.py` and never
   skips; the external script is no longer referenced.
2. Decisiveness proven both ways: passes the committed ramp; fails a non-monotone edit, a
   collapsed adjacent pair, a hue pushed out of band, and a lightened dark `--card`.
3. Full suite green; the 15 pre-existing "validate_palette.py not found" skips drop to zero.

## Also in scope (small, same hygiene class)

- Canonical JS runner: `node --test scripts/cairn/tests/js/*.test.js` (the finish-feature gate)
  passes while `node --test scripts/cairn/tests/js` (the directory form) reports a failure because
  `helpers.js` is picked up as a test. Make the directory form pass too (rename to `_helpers.js`
  or exclude), so "the JS tests pass" has one meaning.
