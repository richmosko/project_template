## Problem

`test_dashboard_chart_ramp.py` guards PT-61's ordinal `--chart-flow-*` ramp with the dataviz
skill's external `validate_palette.py`. On a harness without it the three validator tests skip,
and a skip is indistinguishable from a pass in a green run. That ramp is the palette that once
shipped two sub-floor values. PT-79 vendored a stdlib categorical validator
(`scripts/cairn/tests/palette_check.py`) for the role palette precisely so its guard never skips;
the ordinal ramp is now the only chart palette still unguarded here.

## Ruling (architect, 2026-09-04, PT-79 review) — SUPERSEDED

That ruling mandated `check_ordinal_ramp(css_text)`. PT-85 retired the ordinal `--chart-flow-*`
ramp in both `app.css` and `variants.css`, so the check has no subject: **do not build it.** The
operative ruling is the architect's gate-1 comment below; the acceptance criteria here are its
amended form.

## Acceptance criteria

Amended by the architect's gate-1 ruling below (2026-09-07); every figure here is measured there.

1. No test module references the external `validate_palette.py`. `palette_check.py` supplies both
   symbols the two modules used — a new `contrast_hex(fg_hex, bg_hex)`, and the existing
   `linear_to_hex(oklch_to_linear_srgb(...))` bridge in place of `_oklch_to_hex`.
2. Decisiveness proven both ways on the vendored path: the committed CSS passes; a gated pair
   pushed below its floor fails the gate; the quantized and float contrast models stay
   independently computed; the OKLCH→hex bridge still reproduces PT-61's 1.33 / 1.91.
3. With the external script unreachable, `test_base_theme_contrast_gate.py` and
   `test_dashboard_chart_ramp.py` run 35 tests with **exactly one** skip — the cross-dimension
   vacuity skip, which is out of scope and stays — against **nine** skips today. Full suite green.
4. One canonical JS command, `node --test "scripts/cairn/tests/js/**/*.test.js"`, named in
   `.claude/skills/finish-feature/SKILL.md` and `scripts/cairn/tests/js/INTERFACE.md`; no ratified
   text names a bare-directory form; `helpers.js` is **not** renamed (measured: it is not the
   cause — node 26.7.0 cannot take a directory positional at all).
