## Comments

### @team-lead — 2026-09-08

Found closing PT-0.12.1 (2026-09-08), the first `cairn archive` since PT-94 E15 landed. `cmd_guard_commit` runs `git diff --cached -- <rel>` without rename detection, so a moved issue (`issues/X.md → archive/issues/X.md`) diffs as 100 % added lines and every historical comment author counts as "someone else's uncommitted hunk" — 16 refusals on the archive commit, all false. The commit was made with `--no-verify` after confirming `git diff --cached -M --name-status` showed pure renames (R100).

Fix: run the cached diff with `-M` (or `--find-renames`) and skip `R` entries whose similarity is 100 %; for partial renames diff against the rename source. One regression test: stage a rename of a multi-author issue into `archive/issues/` and assert guard-commit returns 0. Same defect class as archive's own precondition note at cairn.py ~L215.

### @team-lead — 2026-09-08

Feature started. Branch: `feature/pt-109-guard-commit-renames`.

**Gate 1 brief (architect):** `cmd_guard_commit` (cairn.py ~L6418) diffs each staged tracker `.md` with `git diff --cached -- <rel>` and counts added comment authors; a `cairn archive` move (`issues/X.md → archive/issues/X.md`) diffs as 100 % added lines, so every historical author trips E15 — 16 false refusals on the PT-0.12.1 close, committed with `--no-verify`. Rule on: (1) `git diff --cached -M --name-status` and skipping `R100` entries (pure renames carry no new hunk); (2) partial renames (`R<100`): diff against the rename source so only genuinely added comments count; (3) whether the guard should also cover `--no-verify` being needed at all for archive — i.e. does `cairn archive` remain the sanctioned path with the guard now rename-aware. Writers: qa → a test staging a multi-author issue rename into `archive/issues/` (guard returns 0) plus a partial-rename case with one added comment by the committer (returns 0) and by another author (returns 1); implementation-lead → `cmd_guard_commit`.
