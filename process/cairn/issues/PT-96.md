## Problem

Split from PT-93 (asks 3 and 4). PT-93's parallel runner takes the suite from 171 s to ~27 s
without touching a single test, so fixture reuse was **not** required for PT-93's AC1. What
remains is the floor: with file-level parallelism the wall time can never drop below the
slowest single file. Measured 2026-09-06 (`scripts/cairn`, per-file `unittest discover -s tests
-p <file>`): test_server 23.06 s, test_otel_receiver_self_stop 18.64, test_dashboard 13.75,
test_show_archived 12.67, test_backfill_tokens 10.55, test_record_mutation 9.88,
test_root_redirect 8.46. test_server alone is the critical path — 10 workers measured 22.59 s,
1.6 % better than 8 workers (22.87 s), because test_server is still running.

## Ask

1. ~~**Fixture reuse**~~ — **the premise is wrong, measured** (gate-1 ruling, 2026-09-06).
   Fixture construction costs 3.8 ms and server construction 7.2 ms; `server.shutdown()` costs
   **501 ms** because 20 call sites in 14 files start `serve_forever()` at its default
   `poll_interval=0.5`. The work is routing those 20 sites through one helper with a short
   interval — no `setUpModule` reuse, so no cross-test isolation is given up.
2. ~~**Consolidation**~~ — **split to PT-98**: measured at ~0.03 s of interpreter start per
   file, it is not a speed lever, and merging coarsens the parallel packing.

## Acceptance criteria

_Amended by the gate-1 ruling, 2026-09-06 — the original AC1 (≤ 8 s every file) and AC2 (≤ 15 s
wall) are both unreachable without shortening a daemon's timing margins or deleting a CLI
boundary; see `process/reviews/PT-96/timings.md` → "What is left above 8 s"._

1. No test file starts `serve_forever()` without an explicit short poll interval: all 20 call
   sites route through one helper in `tests/helpers.py`, and `grep -rn "serve_forever" tests/`
   returns hits only in `helpers.py` and in comments. Control: the same grep matches 20 live
   sites in 14 files at b0cc8bd.
2. Suite wall at default jobs **≤ 22 s** (measured 19.93 s with the fix; the floor is
   `test_otel_receiver_self_stop.py` at 18.6 s, so 15 s was never reachable here), with counts
   identical to serial `discover` — **1408 tests, skipped=1** (1402 at b0cc8bd plus the 6 qa
   added this loop) — and `--serial` agreeing.
3. No file over 8 s **except** `test_otel_receiver_self_stop.py` and `test_backfill_tokens.py`,
   both deferred to PT-98 with their reasons. Before/after for every file in
   `process/reviews/PT-96/timings.md`.
4. `process/reviews/PT-96/mutations.md` carries one row per converted file: the mutation and the
   test it turns red. A green suite after this change is a prompt, not a result.
5. No test deleted, no test semantics changed; `cairn check` ok; consolidation does not ship.
6. `run_tests.py`'s `main()` calls `run_all()` rather than re-implementing it.

### @architect — 2026-09-06

**Gate 1 ruling — the ask's premise is wrong, and the real cause is one default argument.** Evidence: `process/reviews/PT-96/timings.md`. Machine 10 cores, py 3.14.7, sha b0cc8bd, cwd `scripts/cairn`.

**Measured.** Ten cycles each, direct: `helpers.copy_fixture_data_dir` **3.8 ms**, `cairn.make_server` + thread start **7.2 ms**, `server.shutdown()` **501.1 ms**. `socketserver.BaseServer.serve_forever()` defaults to `poll_interval=0.5` and `shutdown()` blocks until that loop next wakes; at `poll_interval=0.01` the same shutdown is **11.1 ms**. Twenty call sites across fourteen test files write `threading.Thread(target=…serve_forever, daemon=True)` with no interval — so fixture construction is 0.4 % of what the ask blamed, and teardown is ~98 % of it. The five files whose per-test median sits at 0.52–0.58 s are each paying exactly one poll interval.

Applied suite-wide without editing a tracked file (a `sitecustomize.py` on `PYTHONPATH` overriding the default; it logs its pid, and **401 processes** loaded it, so the construction confirms its own subject started): serial **176.6 s → 109.6 s**, parallel default jobs **26.4 s → 19.9 s**, both `Ran 1402 tests … OK (skipped=1)`. **Control**: the identical shim at the stock `0.5` gives 26.74 s, indistinguishable from unpatched — the gain is the interval, not the shim.

**Decided.**
- Ship: route all 20 sites through one helper. **No `setUpModule` reuse** — it was never the cost, and not doing it means no cross-test isolation is traded away. That is the whole speed change.
- AC1 (≤ 8 s everywhere) and AC2 (≤ 15 s) were unreachable and are **amended in place** above. After the fix two files remain over 8 s: `test_otel_receiver_self_stop.py` 18.64 s (real daemon waits; `GRACE` is already 0.4, the rest is deliberate slack — cutting it trades flake risk on a timing contract) and `test_backfill_tokens.py` 11.27 s (40 tests × a real CLI subprocess; in-processing it deletes the boundary the tests exist for). Both → **PT-98**, with reasons, not silently.
- Consolidation (ask 2) → **PT-98** as hygiene. Measured: a file costs ~0.03 s of interpreter start (PT-93: `-j1` 173.84 s vs `discover` 171.44 s over 82 files), and merging coarsens the packing at 8 workers. It is not a speed lever; do not let it ride as one.
- `run_tests.py` `main()`/`run_all()` duplication: taken, AC6.

**Seam** — one helper in `tests/helpers.py`, nothing else moves:
```
SERVE_POLL_INTERVAL = 0.01
def serve_in_thread(server, poll_interval=SERVE_POLL_INTERVAL) -> threading.Thread:
    thread = threading.Thread(target=server.serve_forever, args=(poll_interval,), daemon=True)
    thread.start(); return thread
```
It **starts only**. Existing `_shutdown`/`addCleanup`/`self.thread` teardown stays exactly where it is at every site — converting teardown too would double-shutdown, and the diff must stay a one-line substitution: `self.thread = helpers.serve_in_thread(self.server)`. Five sites are function-local (`test_dashboard_board_embed` 232, `test_dashboard_flow` 171, `test_frontmatter_rewrite` 313, `test_migrate_archive_issues` 386, `test_tokens_endpoint` 311) and take the same one-liner without a `self`.

**Guard thresholds** — qa's red tests in a new `tests/test_serve_in_thread.py`:
1. `grep`-equivalent scan of `tests/*.py`: zero occurrences of `threading.Thread(` with `serve_forever` outside `helpers.py`. Control the scan against a string that must match (`helpers.py`'s own site) so an empty result can't come from a broken pattern — at b0cc8bd this scan finds 20 sites in 14 files.
2. `serve_in_thread` passes the interval to `serve_forever` positionally via `args`: assert with a fake server recording its call.
3. Latency: a real `cairn.make_server(port=0)` started through the helper shuts down in **< 100 ms** (measured 11.1 ms — 9× margin, and 5× under the 501 ms it replaces). Mutation: drop `args=` → ~501 ms → red.
4. `helpers.SERVE_POLL_INTERVAL <= 0.05`.
5. `run_tests.main()` calls `run_all()`: patch `run_tests.run_all`, assert it was called with the ordered file list and the resolved job count. Mutation: restore the inline timer+`_aggregate` → never called → red.

**Writers** — one per file, no overlap. **implementation-lead**: `tests/helpers.py`, the 14 call-site files, `scripts/cairn/run_tests.py`. **qa-engineer**: `tests/test_serve_in_thread.py` (new), `tests/test_run_tests.py`, `process/reviews/PT-96/mutations.md`. Nobody else touches a test file this loop.

**AC4's form.** `process/reviews/PT-96/mutations.md`, one row per converted file: `| file | sites | mutation | test it turns red |`. The mutation is uniform (revert that site to the no-interval `threading.Thread`), so guard 1 is what keeps the table from being vacuous — it makes an unconverted site impossible, per file.

Proceeding on this unless the file says otherwise.

**Addendum 1 — the builder's setUpModule claim, measured; ruling unchanged.**

The claim is **confirmed, and it is stronger than stated**. `test_otel_receiver_self_stop.py` carries the PT-91 real-data-file guard in `setUpModule`/`tearDownModule` (lines 275/303: it snapshots `token-usage.jsonl`, `.receiver.pid` and `.sessions/`, and a `ZZZGuardCoverageProbeTests` sentinel proves the guard armed before any test ran). It *also* holds `_NEW_MODULE_SCOPED_GUARD_TEMPLATE` (line 389) — a `setUpModule`/`tearDownModule` pair written to disk and run as a subprocess, so the module-scoped guard mechanism is itself the subject under test. Layering a fixture-reuse `setUpModule` there would mutate a guard the file exists to prove. It is excluded, and the reason is now on the record.

The wider half of the claim does not need adjudicating, because the payoff is not there. Instrumented count of every `helpers.copy_fixture_data_dir` call in a full run (counting shim on `PYTHONPATH`, per-process totals summed at exit): **200 calls** across 1402 tests. At the measured 3.8 ms per copy that is **0.76 s** — 0.7 % of the post-fix 109.6 s serial suite. A perfect read-only/mutating class split across all six remaining files, done without error, is worth under one second and costs cross-test isolation. It does not ship. The six files split cleanly or not is therefore moot for this loop; if PT-98 ever wants it, it wants it for isolation-hygiene reasons, not speed.

**The failing axis.** AC6's dedup silently dropped the failing child's captured output. Construction, same probe file created/run/deleted in the tree at c36af58: a deliberately failing `tests/test_zz_pt96_probe.py` produces exactly three lines — `FAIL test_zz_pt96_probe.py (0.04s)`, the `Ran`/`FAILED` summary — and `grep -c "expected-marker"` on the whole output is **0**. Control, identical probe and identical tree, against `git show 666d420:scripts/cairn/run_tests.py`: the full traceback prints, `AssertionError: 'expected-marker' != 'actual-marker'` included. So the loss is the change, not the probe.

**Why it blocks.** `run_tests.py` is the `/finish-feature` hard gate and the tiered-run command every teammate now uses. A red suite currently names the file and nothing else — every failure costs a manual re-run to see the traceback, on the one path where the operator is already blocked. The PT-93 ruling fixed this output contract explicitly ("A failing file prints its captured stdout+stderr, then a `FAIL <name> (<s>s)` line"); `run_all` returns no outputs, so `main` has nothing to print. It was not caught because no test asserts on failure *diagnostics*, only on the exit code and `failed_files`.

**Deltas — one batch, `scripts/cairn/run_tests.py` (implementation-lead) + `tests/test_run_tests.py` (qa):**
1. **Blocking.** `run_all` returns the failed children's captured output — e.g. `agg["outputs"] = {name: text}` populated for failing files only, so the aggregate stays small on a green run — and `main` prints each failing file's output above its `FAIL` line, restoring the PT-93 contract exactly. Red test: a fake runner whose child exits non-zero with a marker string in stderr; assert the marker appears in `main()`'s captured stdout. Mutation that turns it red: drop the print. Add a second assertion that a *green* run prints no per-file output, so the guard can't pass by printing everything always.
2. **Non-blocking, same batch.** A test calling `run_tests.main()` lets it write to the real stdout: a full `discover` run now emits a stray `Ran 2 tests in 0.010s (2 files, 3 workers)` / `OK (skipped=0)` pair after the suite's own summary. Harmless to exit codes, but PT-93 kept that exact line shape so external greps would survive, and there are now two of them. Capture stdout in `MainCallsRunAllTests`.

Everything else is accepted at c36af58. Land the two deltas and this verdict stands without a re-review — re-run the probe construction plus `test_run_tests.py`, not the full suite.
