## Problem

Split from PT-93 (asks 3 and 4). PT-93's parallel runner takes the suite from 171 s to ~27 s
without touching a single test, so fixture reuse was **not** required for PT-93's AC1. What
remains is the floor: with file-level parallelism the wall time can never drop below the
slowest single file. Measured 2026-09-06 (`scripts/cairn`, per-file `unittest discover -s tests
-p <file>`): test_server 23.06 s, test_otel_receiver_self_stop 18.64, test_dashboard 13.75,
test_show_archived 12.67, test_backfill_tokens 10.55, test_record_mutation 9.88,
test_root_redirect 8.46. test_server alone is the critical path — 10 workers measured 22.59 s,
1.6 % better than 8 workers (22.87 s), because test_server is still running.

## Ask

1. **Fixture reuse** in the top seven files: build the git fixture repo / spawn the daemon once
   per module (`setUpModule`) where tests only read it; per-test construction stays only where a
   test mutates the fixture. Re-measure per file with `run_tests.py --json`.
2. **Consolidation**: merge per-feature sliver files (2–5 tests on one subject) by subject;
   retire tests whose subjects were retired (PT-85's ramp guard is one). Same count discipline
   as PT-87: delete no test whose rule is still true; record each retirement on this issue.

## Acceptance criteria

1. No single test file exceeds 8 s (`run_tests.py --json`, `times` map), before/after recorded.
2. Suite wall time at default jobs ≤ 15 s; identical pass/skip counts to serial `discover`.
3. A green suite after a fixture change is a prompt, not a result: each converted file names the
   mutation that still turns each affected test red (WORKFLOW → Loop discipline).
4. No test deleted without a comment on this issue naming the retired rule; `cairn check` ok.
