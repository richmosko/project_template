## Problem

Nothing records what past issues cost to deliver. The only record is the local Claude Code
transcripts under `~/.claude/projects/-Users-mosko-Projects-project-template/` (57 files on
2026-09-03; nested subagents in `<session>/` subdirectories). They are outside the repo and
Claude Code prunes them on its retention window, so the history is decaying now.

Each `assistant` record carries `message.usage` (`input_tokens`, `cache_creation_input_tokens`,
`cache_read_input_tokens`, `output_tokens`), `message.model`, `timestamp`, `gitBranch`, and
`agentName` (absent for the lead). Verified 2026-09-03: bucketing by `gitBranch` → PT id and
`agentName` → role gives a clean per-issue, per-role table.

## Scope ruling (team-lead, 2026-09-03, per user)

This is a **one-time scrape**, not an ongoing process. It reads the transcripts once and records
**token usage only**: counts per issue, role, and model, split input vs output, with cache read
and cache write kept separate from fresh input. **No transcript content, no prompts, no tool
output, no message text, no session ids are recorded.** The transcripts themselves are never
copied into the repo. Ongoing collection is PT-78; the chart is PT-79.

## Acceptance criteria

1. A script under `scripts/cairn/` (name is the architect's call; not a permanent `cairn`
   subcommand) scans the transcript directory for this project, dedupes by `requestId`
   (fallback `uuid`), and buckets by issue (`feature/pt-NN-*`, `chore/pt-NN-*` → PT-NN; anything
   else → `main`) and role (`agentName`, default `team-lead`).
2. Output is a single committed data file under `process/cairn/` in the **same schema PT-78 will
   write**, so the two sources merge without translation. Per issue × role × model: fresh input,
   cache write, cache read, output. Plus a `source: transcript-backfill`, a `generated`
   timestamp, and the date window covered. Nothing else.
3. The `main` bucket is kept as its own bucket, not spread across issues.
4. The script fails loudly on a missing field; it never silently under-counts.
5. Tests in `scripts/cairn/tests/` run it against a **synthetic** fixture transcript (duplicate
   `requestId`, a lead record with no `agentName`, a subagent record in a subdirectory, a record
   on `main`). No real transcript is checked in as a fixture.
6. `process/TRACKER.md` gets a short note: what the file is, that it was produced once, and that
   PT-78 owns the ongoing path.
7. `cairn check` passes. No network call.

### 1. The data file

**Path:** `process/cairn/metrics/token-usage.jsonl` (new `metrics/` subdir). — `_dir_glob` globs `*.md` only, inside `issues/` `milestones/` `majors/` `archive/`, and nothing scans the data-dir top level, so this file is invisible to every loader and to `cairn check`.

**Format:** JSON Lines — one object per line, UTF-8, LF, trailing newline. — PT-78 AC4 requires an appender that loses nothing when it dies; appending a line is crash-safe, a single JSON object forces read-modify-write on every flush.

**Granularity:** bucket totals only — one line per (source, issue, role, model) per contribution run. No per-session rows, no session ids, no sub-window timestamps. — the privacy scope ruling, and per-datapoint rows would put transcript-shaped volume into git.

**Schema** — exact keys, all required unless marked optional:

```json
{"source":"transcript-backfill","generated":"2026-09-03T21:04:11Z","window_start":"2026-08-18","window_end":"2026-09-04","issue":"PT-28","role":"implementation-lead","model":"claude-sonnet-5","input":1234,"cache_write":56789,"cache_read":901234,"output":5678,"cache_write_5m":0,"cache_write_1h":56789,"records":412}
```

- `source` — `transcript-backfill` | `otel`.
- `generated` — RFC3339 UTC, `Z` suffix.
- `window_start` / `window_end` — `YYYY-MM-DD` UTC, inclusive, derived from the contribution's own data (not "now").
- `issue` — `<PREFIX>-<n>` or `main`.
- `role` — normalised agent name (§4).
- `model` — raw model string, unmapped. — PT-79's price table keys on it; a normalisation here would need undoing there.
- `input` / `cache_write` / `cache_read` / `output` — ints, the four canonical counters, 1:1 with OTel `type` = `input` / `cacheCreation` / `cacheRead` / `output`. **Authoritative for all totals.**
- `cache_write_5m` / `cache_write_1h` — optional ints, backfill only. OTel has no such attribute, so omitting them is not a translation. **Never sum these in place of `cache_write`:** across the corpus they total 216,247,562 against `cache_write`'s 216,245,870 — they disagree by 1,692 tokens. Keep them because this repo's cache writes are **100% 1-hour** (5m total: 0), and the 1h write rate differs from the 5m rate; discarding the split hands PT-79 a materially wrong cost.
- `records` — optional int, deduped API records folded into the bucket. Sanity/QA only.
- **No other keys.** The script reads `type`, `requestId`, `uuid`, `timestamp`, `gitBranch`, `agentName`, `message.model`, `message.usage.*` and nothing else; `message.content` is never touched.

**Line order:** issues by numeric id ascending, `main` last, then role, then model, then source. — git diffs and fixture assertions need determinism.

### 2. Merge semantics

- **Totals = plain sum over every line.** No last-wins, no read-time keying.
- **A regenerating source rewrites only its own lines:** read all lines → drop every line whose `source` equals its own → append its fresh lines → write via temp + `os.replace`. — re-running is idempotent and otel lines survive byte-for-byte.
- **An appending source only appends, never rewrites.** — a rewriting appender can lose a concurrent append.
- Both take an exclusive lock at `process/cairn/metrics/.lock` (`O_CREAT|O_EXCL`, treat as stale after 60s) before writing.
- **Non-overlap invariant:** no two lines from different sources may cover overlapping windows for the same bucket. The backfill sets `window_end` to its `generated` date; PT-78 must never emit data predating its own start. There is no cross-source dedupe — overlap is a silent double count.

### 3. The script

- **`scripts/cairn/backfill_tokens.py`**, run directly (`python3 scripts/cairn/backfill_tokens.py`). Not a `cairn` subcommand — it is one-time, and `check_dist_freshness.py` is the standing precedent for a standalone script in that dir.
- **Transcript dir default:** `~/.claude/projects/<slug>`, slug = absolute repo root with `/`, `_`, and `.` each replaced by `-`. Verified today: `/Users/mosko/Projects/project_template` → `-Users-mosko-Projects-project-template`, the only matching dir on this machine. (The `.` rule is untested — no dot in this path — but costs nothing and the script fails loudly if the dir is absent.)
- **Missing dir → error + non-zero exit, never an empty result.** — TRACKER's standing rule: "no tracker here" and "no data here" must not render identically.
- **Flags:** `--transcript-dir PATH` (override), `--out PATH` (tests), `--dry-run` (summary to stdout, write nothing).
- **Scan:** recursive `**/*.jsonl`. Nested subagent transcripts live at `<session>/subagents/agent-*.jsonl` (4 today); `memory/` and `<session>/tool-results/` hold no `.jsonl`, so the recursive glob needs no exclude list.
- **Record filter:** keep `type == "assistant"` carrying `message.usage`. **Skip `message.model == "<synthetic>"`** — 8 today, all-zero usage, no `requestId`, no API call behind them.
- **Fail loudly** (error naming file + line number, non-zero exit, nothing written): absent `gitBranch`, absent `message.model`, or any of the four counters missing. All four are present on all 30,281 records today, so an absence is news, not noise.
- **One tolerated skip:** a malformed **final** line of a file — Claude Code appends live (the corpus grew 38 records between two reads minutes apart). Warn, skip, continue. A malformed line anywhere else is a hard fail.
- **Prefix from `process/cairn/config.yml`** (`prefix: PT`), never hardcoded — the template ships to other projects.

### 4. Branch → issue, `agentName` → role

**Issue:** `^(?:feature|chore)/<prefix>-(\d+)(?![\d.])`, case-insensitive, anchored. Everything else → `main`.

- Case-insensitive and slug-optional because `feature/PT-47`, `feature/PT-48`, `feature/PT-49`, `feature/PT-51`, `feature/PT-53` exist with no trailing description.
- **The `(?![\d.])` guard is load-bearing.** `chore/pt-0.11-token-accounting`, `chore/pt-0.10-ledger-hygiene`, `chore/pt-0.8-dashboard-setup`, `chore/pt-0.7.1-setup` are **milestone** branches — they must land in `main`, not a fabricated `PT-0`. PT-79 joins these keys against issue files; a milestone id in an issue-keyed bucket breaks that join.
- **Multi-issue branches attribute wholly to the first id** (`feature/pt-7-8-9-13-cli-hardening` → PT-7, `feature/pt-10-11-drawer-fixes` → PT-10, `feature/pt-21-23-close-0.5.1` → PT-21). — the transcript carries no finer signal; any split would be invented. Note it in the TRACKER blurb.
- `phase/*` and `feature/cairn-engine` → `main`, as intended.

**Role:** `agentName`; absent → `team-lead` (8,220 records today).

- **Normalise by stripping a trailing `-<digits>` only when the stem is a roster name** (a file in `.claude/agents/*.md`): `qa-engineer-76` → `qa-engineer`, `qa-engineer-2` → `qa-engineer`, `implementation-lead-2` → `implementation-lead`.
- **Everything else verbatim, no alias guessing:** `impl` (537), `impl2` (470), `guide-pt18` (19), `qa-pt18` (20), `roundtrip-probe` (9). — `impl`/`impl2` were *probably* implementation-lead sessions; "probably" does not belong in committed data. The script prints unknown role names to stderr; folding them later is a deliberate one-line alias dict.

### 5. Dedupe key

**`requestId`, falling back to `uuid`, deduped globally across all files — not per file.**

- Measured: 30,281 records → **16,508 unique keys**; **11,027 requestIds appear more than once** and **zero duplicates disagree** on (four counters, model, `gitBranch`, `agentName`). Skipping dedupe inflates totals ~1.83×.
- `uuid` is unique across all records; the fallback fires only on `<synthetic>` records, which are filtered first, so it is defensive today. Keep it anyway — one line, and the AC asks for it.
