## Problem

Nothing on the board says what an issue cost to deliver. The data already exists: every
Claude Code session (lead and each tmux teammate) writes a transcript under
`~/.claude/projects/-Users-mosko-Projects-project-template/<session>.jsonl`, and every
`assistant` record carries `message.usage` (`input_tokens`, `cache_creation_input_tokens`,
`cache_read_input_tokens`, `output_tokens`), `message.model`, `timestamp`, `gitBranch`, and
`agentName` (absent for the lead). Nested subagents write into `<session>/` subdirectories.

Verified 2026-09-03 across 57 transcripts: bucketing by `gitBranch` → PT id (`feature/pt-NN-*`,
`chore/pt-NN-*`) and `agentName` → role produces a clean per-issue, per-role table. Sample,
PT-69: implementation-lead 495 calls / 353K output tokens; qa-engineer 356 / 281K; team-lead
126 / 77K; architect 139 / 152K; ux-designer 131 / 129K.

## Constraints surfaced at filing (team-lead, 2026-09-03)

- **Transcripts are the only source.** Claude Code here runs on a claude.ai subscription
  (OAuth), not an API key. The Anthropic Usage & Cost Admin API reports API-org spend only and
  needs an Admin key; it does not see subscription sessions. Claude Code's OpenTelemetry export
  (`CLAUDE_CODE_ENABLE_TELEMETRY`) emits per-session token and cost metrics live but needs a
  collector and does not backfill. The transcript scan is the systematic path; cost is
  estimated locally from a checked-in price table keyed by `message.model`.
- **Transcripts are not durable.** They live outside the repo and are pruned by Claude Code
  (`cleanupPeriodDays`, default 30). The collector must write a committed snapshot into
  `process/cairn/` and merge on re-run, never overwrite, so history accumulates in git.
- **Cache reads dominate volume** and are priced at a fraction of fresh input. A tokens-only
  chart misleads; input vs output must be separate series, and cache read / cache write must be
  distinguishable from fresh input (at minimum in the drawer, ideally as a stacked sub-series).
- **Work on `main` does not attribute to an issue.** Filing, release closes, and status
  conversations land in a `main` bucket. Show it honestly as its own bar; do not spread it.
- **Dedupe by `requestId`** (falls back to `uuid`): a retried or resumed turn can appear twice.
- **Undocumented format.** The JSONL shape is Claude Code internal. The collector fails loudly
  on a missing field rather than silently under-counting; a fixture transcript pins the shape.

## Acceptance criteria

1. `scripts/cairn/cairn tokens` scans the transcript directory for this project (derived from
   the repo path the same way Claude Code derives it; overridable by flag), dedupes, buckets by
   issue (branch) and role (`agentName`, default `team-lead`), and writes
   `process/cairn/tokens.json` (name is the architect's call) with per-issue, per-role,
   per-model counts of fresh input, cache write, cache read, and output tokens, plus a
   `generated` timestamp and the transcript window covered. Re-running merges; nothing is lost.
2. A checked-in price table (per model: input, cache write, cache read, output, $/MTok) drives
   an estimated cost per bucket. The table is data, not code, and is dated.
3. The board serves the snapshot on an API path and the dashboard gets a new block beside the
   PT-61 chart: one bar per issue, stacked by role, with a toggle between **tokens (input vs
   output as separate series)** and **estimated cost**. Existing dashboard tests extend to it.
4. The issue drawer shows the issue's total tokens and estimated cost with the role split.
5. Tests in `scripts/cairn/tests/` cover the collector against a fixture transcript (including
   a duplicate `requestId`, a lead record with no `agentName`, a subagent record in a
   subdirectory, and a record on `main`) and the merge-on-rerun behaviour.
6. `process/TRACKER.md` documents the subcommand, the snapshot schema, the price table, and
   when to run the collector (recommended: `/finish-feature` runs it before commit so the
   snapshot lands in the feature PR).
7. No live network call anywhere on the path. `cairn check` passes.
