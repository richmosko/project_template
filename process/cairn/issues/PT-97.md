## Problem

Split from PT-93 (team-lead's 2026-09-05 comment). PT-94 landed the *rule* — C9, one full-suite
run per gate by the gate owner, everyone else runs the touched module — in every agent
definition. PT-93 lands the *runner* and the tiered command. This issue is the mechanical half:
nothing today stops an agent from running the full suite 16 times in a loop, and
`cairn loop-stats` prints `(unmeasured — PT-93)` for its `suite_seconds_added` row because no
run is recorded anywhere.

## Ask

1. ~~`cairn test` subcommand~~ — **not built** (gate-1 ruling, 2026-09-06): a PostToolUse Bash
   hook carries `agent_type`, `duration_ms` and the runner's stdout, so it can write the record
   itself for `run_tests.py` and `unittest discover` alike. That leaves the wrapper one job —
   declaring the gate — which `run_tests.py --gate {red,green,verdict,finish}` does directly.
   Records land in `process/cairn/metrics/test-runs.jsonl`.
2. PreToolUse Bash hook that refuses a bare `unittest discover -s tests` with no `-p`/`-k`
   unless it came from `cairn test --full --gate …`. Must not fire on the finish-feature gate
   or on a human's ad-hoc run outside a loop.
3. `cairn loop-stats <ID>` fills `suite_seconds_added` and a full-run count from those records,
   against the soft cap of 4 full runs per loop.

## Acceptance criteria

_Amended by the gate-1 ruling, 2026-09-06._

1. The PreToolUse guard refuses a teammate's un-tiered full run — `run_tests.py` **or**
   `unittest discover -s tests` with no `-p`/`-k` — and its message names both `-p` and the
   `--gate` form; a `--gate` run and a `-p` run pass; an unknown or absent `agent_type` always
   passes, which is the human/lead lane. Ten branches, each with a test naming its red mutation.
2. `cairn loop-stats <ID>` derives `full_suite_runs` and `suite_seconds_added` from
   `process/cairn/metrics/test-runs.jsonl`, printing numbers or
   `(no full-run records in window)` — never `(unmeasured — PT-93)`; and `classify_bash`
   recognises a narrowing-free `run_tests.py` as FULL_SUITE.
3. Hook cost measured and recorded **with the shell prefilter shipped** (addendum 1): ~6 ms per
   Bash call on a glob miss and 32 ms on a hit, against 29 ms for an unconditional python hook
   and a 27 ms interpreter floor — `process/reviews/PT-97/measurements.md`.
4. Every `.claude/hooks/` command in `.claude/settings.json` is `$CLAUDE_PROJECT_DIR`-anchored,
   `message_cap.py` included, with a guard whose control is the one unanchored command at
   09a0843.

### @architect — 2026-09-06

**Addendum 1 — shell prefilter, taken as decided.** Verified end to end against the captured payload, not reasoned about: exit 2 propagates through the pipe (a bare `run_tests.py` is still blocked), `-p` still passes, and a non-test command never spawns python.

Both hook registrations in `.claude/settings.json` take this exact form, differing only in the script name:

    in=$(cat); case "$in" in *unittest*|*run_tests*) printf %s "$in" | python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/test_run_guard.py";; *) exit 0;; esac

(and `test_run_record.py` for PostToolUse). `"$in"` must stay quoted; `printf %s` avoids re-interpreting the JSON; the pipeline's status is python's, which is what makes the block work.

**The glob matches the whole payload, not just the command — deliberately.** A false positive costs 29 ms and python then decides correctly; only a false *negative* is dangerous, because it skips the guard silently. Matching the whole envelope makes false negatives strictly less likely.

**Coupling guard.** `test_run_guard.py` exposes `TEST_CMD_TOKENS = ("unittest", "run_tests")` and the guard's own matcher is built from it. qa asserts that every token has a `*<token>*` alternative in each `settings.json` hook command, so the two can never drift. Red mutation for AC1, as decided: narrow the glob to `*unittest*` only, then feed the captured payload with `command = "cd scripts/cairn && python3 run_tests.py"` — python is not spawned, the run is not blocked, and the test must go red on exactly that.

**AC3's recorded number is now the prefiltered cost** (amended in place above): **~6 ms** per Bash call on a glob miss — measured 0.13 s / 20 with one extra `sh -c` of harness overhead, 0.08 s / 20 for the prefilter alone — against 29 ms for the unconditional python hook and a 27 ms interpreter floor. A hit costs 32 ms, i.e. the prefilter adds ~3 ms to the runs it does not skip. Full table: `process/reviews/PT-97/measurements.md`.

Cap of 4 full runs stays this loop, re-derived from records on PT-94's next pass. Everything else in the ruling @a23e832 stands.
