## Problem

Split from PT-93 (team-lead's 2026-09-05 comment). PT-94 landed the *rule* — C9, one full-suite
run per gate by the gate owner, everyone else runs the touched module — in every agent
definition. PT-93 lands the *runner* and the tiered command. This issue is the mechanical half:
nothing today stops an agent from running the full suite 16 times in a loop, and
`cairn loop-stats` prints `(unmeasured — PT-93)` for its `suite_seconds_added` row because no
run is recorded anywhere.

## Ask

1. ~~`cairn test` subcommand~~ — **not built** (gate-1 ruling, 2026-09-06): a PostToolUse Bash
   hook carries `agent_type`, `duration_ms` and the runner's stdout, so it can write the record
   itself for `run_tests.py` and `unittest discover` alike. That leaves the wrapper one job —
   declaring the gate — which `run_tests.py --gate {red,green,verdict,finish}` does directly.
   Records land in `process/cairn/metrics/test-runs.jsonl`.
2. PreToolUse Bash hook that refuses a bare `unittest discover -s tests` with no `-p`/`-k`
   unless it came from `cairn test --full --gate …`. Must not fire on the finish-feature gate
   or on a human's ad-hoc run outside a loop.
3. `cairn loop-stats <ID>` fills `suite_seconds_added` and a full-run count from those records,
   against the soft cap of 4 full runs per loop.

## Acceptance criteria

_Amended by the gate-1 ruling, 2026-09-06._

1. The PreToolUse guard refuses a teammate's un-tiered full run — `run_tests.py` **or**
   `unittest discover -s tests` with no `-p`/`-k` — and its message names both `-p` and the
   `--gate` form; a `--gate` run and a `-p` run pass; an unknown or absent `agent_type` always
   passes, which is the human/lead lane. Ten branches, each with a test naming its red mutation.
2. `cairn loop-stats <ID>` derives `full_suite_runs` and `suite_seconds_added` from
   `process/cairn/metrics/test-runs.jsonl`, printing numbers or
   `(no full-run records in window)` — never `(unmeasured — PT-93)`; and `classify_bash`
   recognises a narrowing-free `run_tests.py` as FULL_SUITE.
3. Hook cost measured and recorded: 29 ms per Bash call, against the 27 ms interpreter floor and
   a 4 ms shell-prefilter alternative — `process/reviews/PT-97/measurements.md`.
4. Every `.claude/hooks/` command in `.claude/settings.json` is `$CLAUDE_PROJECT_DIR`-anchored,
   `message_cap.py` included, with a guard whose control is the one unanchored command at
   09a0843.

### @architect — 2026-09-06

**Gate 1 ruling.** Measurements and the real captured payloads: `process/reviews/PT-97/measurements.md`, `process/reviews/PT-97/hook-payloads.json`. Probed live via a throwaway hook in the gitignored `settings.local.json`, restored after; `.claude/settings.json` untouched.

**Measured, and it changes the design.** A PreToolUse Bash hook receives **`agent_type`** — observed `"architect"` and, from a concurrently-running session, `"implementation-lead"`. Attribution needs no transcript walk. PostToolUse receives the same envelope **plus `duration_ms` and `tool_response.stdout`**; against a real `run_tests.py -p …` the stdout was `Ran 29 tests in 0.079s (1 files, 8 workers)`. So who / gate / seconds / files / tests are all available **after** a run, for `run_tests.py` and `unittest discover` alike. `$CLAUDE_PROJECT_DIR` is set in the hook shell (to the repo root) in the very invocation whose `$PWD` was `scripts/cairn` — that is the message_cap breakage, reproduced and anchored.

**Decided.**
- **No `cairn test` subcommand** (departs from ask 1). Recording moves to a PostToolUse hook, which leaves a wrapper with one job — carrying the gate marker — and `run_tests.py` can carry that itself. Add `--gate {red,green,verdict,finish}` to `run_tests.py`; no new entry point, no `cairn.py` dispatch.
- **`verdict` is a gate.** The architect's gate-4 measurement is a full run — three of them on PT-96 (default, `--serial`, `discover`). A vocabulary of red/green/finish would have refused my own verdict work.
- **The hook does not police owner↔gate pairing**, only that a full run declares *a* gate. Pairing would block the case above and every legitimate re-measure.
- **Python-only hook, no shell prefilter.** Measured 29 ms per Bash call (interpreter start; the logic is ~2 ms) against 4 ms for a `case`-glob prefilter. The 25 ms is real but a JSON-escaped shell glob in `settings.json` is precisely the class of thing that breaks silently — message_cap is the precedent. If you want the 25 ms, say so and it is one line.

**Seam.**
- `.claude/hooks/test_run_guard.py` (PreToolUse, matcher `Bash`), in order: unparseable stdin → 0; `tool_name != "Bash"` → 0; `agent_type` **not** a stem of `.claude/agents/*.md` → 0; command is not a full-suite run → 0; command contains `--gate <red|green|verdict|finish>` → 0; else **exit 2** naming both `run_tests.py -p "test_<area>*.py"` and the gate form. Full-suite run means `run_tests.py` or `unittest discover -s tests` with no `-p`/`-k`. Every unknown case exits 0 — that, not a heuristic, is what keeps it off a human's shell and off the lead's finish gate (the main session's `agent_type` was not captured, and the rule does not depend on it; there is no `.claude/agents/team-lead.md`).
- `.claude/hooks/test_run_record.py` (PostToolUse, matcher `Bash`): if the command is a test run, append one line to `process/cairn/metrics/test-runs.jsonl` under `$CLAUDE_PROJECT_DIR`; otherwise write nothing. Schema, one JSON object per line: `ts, who (agent_type or null), gate, full (bool), runner ("run_tests"|"unittest"), sha, branch, seconds, harness_ms, files, tests, skipped, ok, session, cmd (first 200 chars)`. `seconds` comes from the parsed `Ran N tests in W s` summary when present, `harness_ms` from `duration_ms` — never one substituted for the other; the gap is shell overhead.
- `.claude/settings.json`: both hooks registered as `python3 "$CLAUDE_PROJECT_DIR/.claude/hooks/<name>.py"`, and `message_cap.py`'s invocation re-anchored the same way.
- `loop_stats.py`: records are authoritative. `full_suite_runs` = records in the loop window with `full: true`; `suite_seconds_added` = last full-run `seconds` − first full-run `seconds` in the window (on PT-96 that reads −6.9 s: 26.4 → 19.5). Fewer than two full records → print `(no full-run records in window)`, never `(unmeasured — PT-93)`. Separately fix `classify_bash` so a `run_tests.py` call with no `-p` classifies FULL_SUITE — today it returns `bash_other`, which is why PT-96 scored 0.

**Guard thresholds** — one red mutation each; none may run the real suite:
1. teammate + bare full run → exit 2, message contains `-p` **and** `--gate`; mutation: return 0.
2. teammate + `--gate green` → 0; mutation: block unconditionally.
3. teammate + `-p "test_x*.py"` → 0; mutation: treat any `run_tests.py` as full.
4. `agent_type` absent/unknown + bare full run → **0**; mutation: default-deny. This is the human/lead lane.
5. malformed stdin → 0; mutation: let the exception escape.
6. teammate + `unittest discover -s tests` with no `-p` → exit 2 (both invocations recognised).
7. recorder against the captured payload in `hook-payloads.json` → one record, `tests=29 files=1 seconds=0.079 runner="run_tests" who="architect"`; mutation: use `duration_ms/1000` as `seconds` when a summary exists.
8. recorder on a non-test Bash call → file unchanged; mutation: always append.
9. `loop_stats` over a fixture jsonl → numeric `full_suite_runs` and `suite_seconds_added`, no `(unmeasured)`; mutation: return None.
10. every `.claude/hooks/` command in `settings.json` is `$CLAUDE_PROJECT_DIR`-anchored. **Control run at 09a0843: 1 such command, 1 unanchored** (message_cap) — the scan finds the known offender.

**Writers.** implementation-lead: both hook files, `.claude/settings.json`, `run_tests.py`, `loop_stats.py`. qa-engineer: `tests/test_test_run_hooks.py` (new), `tests/test_loop_stats.py`, and the settings-anchoring guard. qa builds fixtures from `process/reviews/PT-97/hook-payloads.json` — real captures, not hand-written; a hand-written payload proves only self-consistency.

Expect PT-96 and PT-97 to read OVER. The cap wants re-deriving from these records once they exist; not this issue's call.
