### @team-lead — 2026-09-08

Architect's carry-forward from PT-113's verdict @58d22af (2026-09-09): `_test_run_shared.is_test_invocation` anchors on the interpreter token being immediately adjacent to the script/module token, so `python3 -X dev scripts/cairn/run_tests.py --gate green` and `uv run scripts/cairn/run_tests.py …` are not recognised — the guard lets an un-tiered full run through and the record hook does not patch `who`. Fix: allow interpreter flags between the two tokens (`-X …`, `-W …`, `-u`, `-B`), and treat `uv run` / `poetry run` as launcher prefixes; truth-table tests both directions incl. the `git add python3.14` false-positive control. ### @team-lead — 2026-09-08

Feature started. Branch: `feature/pt-115-hooks-flags-launchers`.

**Gate 1 brief (architect):** `.claude/hooks/_test_run_shared.py::find_runner_invocation` (~L61) requires the interpreter token to be immediately followed by the runner/module token, so `python3 -X dev scripts/cairn/run_tests.py --gate green`, `python3 -W error …`, `python3 -u …`, and launcher prefixes (`uv run …`, `poetry run …`) are not recognised: the PreToolUse guard lets an un-tiered full run through and the PostToolUse hook does not record it (and after PT-113, loop_stats' `classify_bash` shares the predicate). Rule on: (1) the accepted interpreter-flag set between the two tokens — a closed allow-list (`-X <arg>`, `-W <arg>`, `-u`, `-B`, `-O`, `-I`, `-E`, `-s`) vs "any dash-token", and how `-m unittest` stays distinct from a flag; (2) which launchers count as prefixes (`uv run`, `poetry run`, `pipx run`?) and whether `uv run python3 …` (launcher + interpreter) is one shape or two; (3) the false-positive controls that must stay negative (`git add python3.14 -X`, a `Read` of the hook, a heredoc quoting the command — PT-111's heredoc stripping is in loop_stats only, not the hooks); (4) whether the `.claude/settings.json` sh prefilter needs widening for `uv run`. Writers: qa → hook tests (+ loop_stats truth-table row); implementation-lead → `_test_run_shared.py` (+ settings.json prefilter if (4) says so).
