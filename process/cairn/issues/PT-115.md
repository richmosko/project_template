### @architect — 2026-09-08

**Gate 1 ruling (architect).** Measured over the whole transcript archive (83 files, **2110 distinct Bash commands / 2604 calls** mentioning `run_tests`/`unittest`), plus the real PreToolUse denials recovered by `tool_use_id`.

**The issue as filed — mine, from PT-113 — has zero measured instances.** No `python3 -X dev …run_tests.py`, no `-W`, `-u`, `-B`, and **no `uv run` / `poetry run` of the runner anywhere in the archive** (uv 0.12.6 and pipx are installed, so the shape is reachable). The only tokens that really sit between an interpreter and its target are `-c` (30 calls) and `-` (75 calls, stdin heredocs) — both of which must stay **non**-runs. A "skip any dash token" rule would swallow exactly the two shapes the data contains.

**What the data does show is the opposite failure: four live false positives, several of which actually refused a teammate's legitimate command.**
1. `python3 -m unittest tests.test_a tests.test_b -v` and `python3 -m unittest tests.mod.Class.test_x` — **3 measured refusals**. Naming modules explicitly *is* narrowing; `is_full_suite_run` only knows `-p/--pattern/-k`.
2. `python3 run_tests.py --help` — **1 measured refusal**. `--help`/`--list` exit without running anything.
3. A heredoc body that *quotes* a run: **8 measured commands**, including `cat > /tmp/pt99-verdict.md <<'EOF' … --gate verdict … EOF` and `cat >> process/cairn/issues/PT-76.md <<'EOF' …`. Writing a verdict file can be refused as an un-tiered full run.
4. (Same root as 3.) `S=…; python3 - <<'PY' …` scratch scripts land in the same trap.

**Ruling — fix the measured false positives first; add the filed evasion second, as it is cheap.**
- **(i) `-m unittest` with a positional target is narrowed.** Only `discover` (or a bare `-m unittest`) is a full suite. This aligns the hooks with `loop_stats._FULL_RE`, which has encoded exactly that since PT-93.
- **(ii) `run_tests.py` carrying `--help`, `-h` or `--list` is not a run** — not full, and no record.
- **(iii) Strip heredoc bodies in `_test_run_shared.tokenize`'s callers, i.e. in the shared module, before the invocation scan. This reverses the rationale in my PT-111 ruling** ("a heredoc quoting a full run should still be refused there") — that was reasoning, this is measurement: 8 real commands, several refused. Move `_strip_heredocs` out of `loop_stats.py` into `_test_run_shared.py`; both callers use the one implementation.
- **(iv) Interpreter flags: a closed allow-list, never "any dash token".** Skip `-u -B -O -OO -I -E -s -q -v -d`, `-X`/`-W` in both the separated (`-X dev`) and attached (`-Xdev`, `-Werror::DeprecationWarning`) forms, and combined short clusters (`-uB`) — all four forms verified against the real interpreter. **Never skip `-c` or `-`**; an unrecognised dash token **stops** the scan rather than being guessed past.
- **(v) Launchers: `uv run` and `poetry run` only**, as a prefix consumed before the normal scan, so `uv run …/run_tests.py` and `uv run python3 …/run_tests.py` are one shape, not two. `pipx run` is excluded — it runs a *package*, not a script. Tagged **(unmeasured)**: no archive instance; included because it is two tokens of code.
- **(vi) `.claude/settings.json` prefilter: no change** (brief item 4 answered). The `case "$in" in *unittest*|*run_tests*` glob matches the raw stdin JSON, which carries the command text; every newly accepted shape still contains one of those substrings.

**Guards (qa writes; red at gate 2).**
1. Accepts: `python3 -X dev …/run_tests.py --gate green`, `python3 -Xdev …`, `python3 -uB -m unittest discover -s tests`, `uv run scripts/cairn/run_tests.py`, `uv run python3 …/run_tests.py`, `poetry run python -m unittest discover -s tests`.
2. Rejects, taken verbatim from the archive: `python3 - <<'PY' …`, `python3 -c "…"`, `pipx run …`, and PT-113's `git add -- 'notes/python3.14 run_tests.py --gate green.md'`.
3. Narrowed, must NOT be refused by the guard: `python3 -m unittest tests.test_x tests.test_y -v` and `python3 -m unittest tests.test_x.Class.test_m`; control — `python3 -m unittest discover -s tests` un-tiered is still refused.
4. `python3 run_tests.py --help` and `--list` are not full runs; control — bare `python3 run_tests.py` still is.
5. Heredoc: `cat > f <<'EOF' … python3 run_tests.py … EOF` is not an invocation **in the hooks** now; controls — the same command with the heredoc body removed is, and `loop_stats`' own heredoc tests stay green through the shared helper.
6. Lockstep: every shape accepted above still contains a `TEST_CMD_TOKENS` substring, so the shell prefilter needs no widening.

**If the lead wants this split:** guards 3–5 are the measured defects and take precedence; guards 1–2 (the filed evasion) can wait without cost.

**Writers.** implementation-lead → `.claude/hooks/_test_run_shared.py` and `scripts/cairn/loop_stats.py` (delegate to the shared `_strip_heredocs`). qa → `scripts/cairn/tests/test_test_run_hooks.py`, `test_loop_stats.py`. No `settings.json`.

**On the reversal.** PT-111's ruling kept heredoc stripping out of the hooks on the reasoning that a heredoc quoting a full run should still be refused. The archive says that reasoning cost 9 real refusals of teammates writing files. The landed code strips in the shared tokeniser, and the 12 detection losses above confirm the change removes only quoted text.

**Carried forward, non-blocking.** `-c` and `-` (stdin) remain deliberately unskippable, so a `python3 -c "…"` that genuinely shells out to the runner is still invisible to the guard — 0 instances in 2604 calls, and skipping them would swallow the 105 calls that must stay negative.
