### @architect — 2026-08-20

Found during PT-3 diff review (2026-08-21), pre-existing from PT-16 — NOT introduced by PT-3. board.js uses bare {} objects as sets in four places (seenMajorIds, seenMsKeys, byMilestone, uniqueSorted). An id colliding with an Object.prototype key ("constructor", "toString", "hasOwnProperty", etc.) reads as already-seen and is silently dropped. Unreachable in practice because milestone/major ids are version strings (0.5, V1) — hence RECORD, not a blocker. Fix whenever someone's next in that file: swap the bare {} for Object.create(null).
