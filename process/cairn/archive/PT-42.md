## Problem

Mosko (2026-08-23): once `cairn archive` sweeps done issues into `archive/`, they vanish from the board with no way to view them. Add a "Show Archived" control on the dashboard (pattern-match the existing Show-cancelled checkbox), default OFF, that folds archived issues back into the full board view.

## Acceptance criteria

- [ ] Architect design ruling first: server surface (does /api/board serve archive/ contents behind a param or always, with client-side filtering? payload-size posture for old repos), where archived cards render (their original milestone lanes? a distinct visual treatment?), and interaction with counts/chips (PT-31/PT-35 invariants — visible must equal counted with the toggle on)
- [ ] Toggle default off; off-state byte-identical to today (reference-identity-style enforcement where possible, per the PT-35 precedent)
- [ ] Archived cards read-only or drag-disabled per ruling (dragging an archived card is a semantics question, not a given)
- [ ] Works with Show-cancelled in both combinations

# PT-42 ruling — Show Archived

## 0. Measurement that decides the server surface

Synthetic repo, 1400 archived + 50 live issues, this machine (min of 7 runs):

| Operation | Cost |
|---|---|
| `build_board_payload` — `issues/` only (today) | **3 ms** |
| + parsing 1400 `archive/` frontmatters | **+83 ms** |
| `compute_etag` today | **0.4 ms** |
| `compute_etag` including `archive/` | **10 ms** |
| `scan_data_dir` (watcher, already globs `archive/`, every 500 ms) | 12 ms |

⇒ Serving `archive/` unconditionally is a **28× regression on the default path** and defeats the
stated reason archiving exists ("so a three-year-old project doesn't parse 1,400 files per
request"). Paying it only when a human asks costs one 83 ms request.

## 1. Server surface: `GET /api/board?archived=1`

- **Off (no param): the identical code path, unchanged.** Not "a filter that happens to remove
  everything" — the same function, the same etag inputs, the same bytes. That is what makes AC2
  ("off-state byte-identical to today") structural rather than asserted.
- **On:** the payload additionally carries archived **issues**, archived **milestones**
  (`archive/milestones/`) and archived **majors** (`archive/majors/`) — see the PT-39 ruling §4.
  **One archive read path for all three record types**, which is the "archive/ isn't read two
  different ways" requirement discharged.
- Every archived record is stamped `archived: true`. Live records are stamped `archived: false`
  — **not** "the key is absent" (no conditional payload shape; PT-3 precedent).
- **Archived issues go into the same `issues` array**, not a parallel `archivedIssues` array.
  This is the load-bearing plumbing decision: a parallel array would need a second counting path,
  and PT-31/PT-35's "visible must equal counted" invariant would become a hand-maintained
  agreement between two producers instead of a property of one.
- ETag: fold the flag into the hash input, and include the archive dirs' `(path, mtime_ns)` when
  the flag is on. An ETag identifies a *representation*; two shapes must never share one.
- Multi-root: applied per root, same as everything else.

## 2. Client

- Checkbox `#filter-archived` "Show archived", **default off**, adjacent to Show cancelled.
  **In-memory only** (`state.showArchived`) — not persisted to localStorage, matching
  `showCancelled` exactly. One convention for view toggles, not two.
- **Any change to a request-shaping parameter clears `state.etag` before the fetch.** Flipping the
  toggle must not send an etag minted for the other shape. Same rule covers the pull-to-refresh
  force-refetch in the PT-40/43/44 ruling §4.

## 3. Where archived cards render

**In their own milestone lane, in their own status column, with a distinct visual treatment**
(`.card.is-archived` — muted + an `archived` chip). Not a separate "Archive" lane or column.

Rationale: PT-43's complaint is precisely that archived work vanished from the milestone it
belongs to. A separate lane would re-break that, and would break "visible must equal counted"
for the milestone it was taken from.

## 4. Counts

No new counting rule. Archived issues are ordinary members of `issues` with column-backed
statuses (`done`, occasionally `cancelled`), so `laneSummary(issues, activeColumns())` already
counts exactly what renders. Consequences, both accepted:

- Turning the toggle on **increases** lane/repo counts. Precedent: Show-cancelled already does
  this (PT-35). A count is of what is displayed; that is the invariant, and it holds in all four
  toggle combinations.
- Show-archived × Show-cancelled: an archived *cancelled* issue renders only when **both** are on.
  Falls out of the existing rules; no special case. Test all four combinations (AC4).

## 5. Archived cards are read-only on the board

- `draggable=false`; no drop handling.
- Drawer opens (viewing archived issues is the whole point) but reuses the **existing** PT-3
  `read_only` suppression path for the inline editors — do not invent a second read-only flag.
- **Server:** `POST /api/issue/<id>` where the id resolves in `archive/` is refused
  `403 {"error": "archived", ...}`, file untouched, mirroring `read_only_root`'s shape.
- **The CLI is deliberately still allowed** to write an archived issue (`cairn set`,
  `cairn comment` — `find_issue_path` already resolves `archive/`). The asymmetry is intentional:
  a drag is a one-pixel gesture that would leave an `in-progress` issue sitting in `archive/`,
  invisible the moment the toggle goes off. Un-archiving is `git mv`, deliberately, as TRACKER.md
  already says.
