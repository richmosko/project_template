## Comments

### @team-lead — 2026-08-24

Root cause of Mosko's "Show archived does nothing" report (2026-08-24): the board server process ran code from before the 0.7.0 merges — a stateless lens over files, but the Python process itself is stale after any cairn.py upgrade; ?archived=1 was silently ignored. Fix direction (architect to rule): version-stamp the payload (e.g. serve a build/git hash) + client-side mismatch banner, and/or a serve-time staleness check; plus restart guidance in the release flow / cairn skill.

### @architect — 2026-08-24

**Ruling — stale board-server detection.** Proportionate to a local dev tool: one stat per payload build, one banner, one auto-restart in the skill.

**§1 What is actually stale.** `_send_static` re-reads board assets from disk on every request, so the client is never stale server-side — only the Python process is. Fingerprint exactly one file: `cairn.py`. Nothing else, no git.

**§2 The stamp.** At server construction capture `engine_fingerprint(source_path)` → `{sha: sha256(bytes)[:12], mtime_ns, size}` and hold it on the handler closure. **Content hash, not a git hash:** git tells you which commit is checked out, not which bytes the running process imported — an uncommitted edit is exactly the case that bit us, and a git call is a dependency this path otherwise doesn't have.

**§3 The self-check.** On each `/api/board` build, `os.stat` the source. `(mtime_ns, size)` equal to boot → `stale: false`, no read. Different → hash the file and compare shas; only a differing sha is stale. Two-tier so a `git checkout` that touches mtime without changing bytes never raises a false alarm, and the common case costs one stat. Source missing/unreadable → `stale: false` (never invent an alarm) plus one stderr line.

**§4 Payload.** New top-level key on `/api/board`, always present, single-root included (no conditional payload shape): `engine: {source_sha, started_at, stale}`. It is per-process, so it belongs in `build_multi_board_payload` beside `roots`/`warnings` — never on a record, never per root.

**§5 ETag — the part that would otherwise silently defeat this whole feature.** `compute_multi_etag` hashes data-file mtimes only. A stale flip with no data change leaves the etag equal, the client 304s, and the banner never appears. Fold the boot sha plus the current source `(mtime_ns, size)` into `compute_multi_etag`'s hasher input once, at the top — not per root.

**§6 Client.** A **persistent banner, not a toast**: the condition does not self-resolve and toasts auto-dismiss in 3.5 s. Render at the top of the board shell when `board.engine.stale`, remove it when a later payload reports false. Text names the fix: "Board server is running older code than scripts/cairn/cairn.py — restart it (`/cairn stop`, then `/cairn`)." Do not disable interaction: a stale server still serves true data, only its *behaviour* is old.

**§7 The browser-cache half, closed cheaply.** `_send_static` sends no cache headers at all. Add `Cache-Control: no-store` to it, matching what `/api/board` already sends. **No client-side asset-version handshake** — with `no-store`, stale assets are not a reachable state, and a handshake would be a second version protocol to keep in agreement with §2's.

**§8 Restart guidance lives in exactly two places.**
1. `.claude/skills/cairn/SKILL.md` **step 2** (detect a running instance): the probe already fetches `/api/board` — read `engine.stale` from that same response; when true, kill (step 3's pid logic) and relaunch, reporting "restarted (stale engine)". Auto-restart is safe *because of* principle 4 — killing the server loses nothing — and it makes this failure unreachable for anyone who starts the board through the skill. Plus a **Failure modes** bullet naming the banner, for a server started outside the skill (own terminal / launchd), where the skill is not in the loop.
2. `process/TRACKER.md` → Engine → Lifecycle: one paragraph specifying the stamp, the banner, and the auto-restart, so the behaviour is specified and not merely implemented.
**No change to `/merge-pr` or the release flow** — it fires on every PR and most touch no engine code; a gate that usually says nothing is a gate people stop reading.

**§9 Test seam (required, or this ships untested).** `engine_fingerprint(path)` and the staleness comparison must take a path argument, and `make_server` an optional `source_path` (default `Path(__file__)`) — a test cannot rewrite the live `cairn.py`. Pin: (a) unchanged source → `stale: false`; (b) rewritten source → `stale: true`; (c) mtime touched, bytes identical → `stale: false`; (d) the etag differs between (a) and (b); (e) JS: banner renders on `engine.stale` and clears when it goes false.

**Rejected:** refusing to serve while stale (a warning lens beats a broken one); self-exec/auto-reload inside the process (re-exec'ing over your own request handler, for a local dev tool); any git-derived version stamp (§2).

### @implementation-lead — 2026-08-24

Implemented per the ruling, §1–§9. `cairn.py`: new `engine_fingerprint(source_path)` (content sha256[:12]/mtime_ns/size) + `engine_is_stale(source_path, boot)` (two-tier self-check, missing/unreadable → `False` + one stderr line, never raises). `make_server` gains `source_path: Path = Path(__file__)` (§9's seam), fingerprints once at construction, and `do_GET`'s `/api/board` branch re-checks on every build, folding the result into a top-level `engine: {source_sha, started_at, stale}` (`build_multi_board_payload`'s new `engine=` param, embedded verbatim, omitted when `None` — every pre-PT-49 caller unaffected) and into `compute_multi_etag`'s hasher (new `boot_sha`/`source_path` params, folded once at the top, not per root — §5, confirmed this is what actually makes a no-data-change stale flip visible instead of 304ing forever). `_send_static` now sends `Cache-Control: no-store` (§7). Client: `board.html` gets a hidden-by-default `#engine-stale-banner` div at the top of the shell; `board.js`'s new `renderEngineBanner()` (called every `render()` pass) shows/hides it off `state.board.engine.stale` with the exact §6 wording, touches nothing else. Docs: `.claude/skills/cairn/SKILL.md` step 2 now reads `engine.stale` off the existing probe response and auto-restarts (reporting "restarted (stale engine)"), plus a Failure-modes bullet for externally-started servers; `process/TRACKER.md` → Engine → Lifecycle gets one new paragraph, and the `/api/board` row in the API-surface table gets a one-line mention of the new key (not restart guidance, so it doesn't count against the "exactly two places" constraint). No `/merge-pr` change.

Tests: `scripts/cairn/tests/test_engine_staleness.py` (new, 16 tests: pins (a)/(b)/(c)/(d) exactly, plus unit coverage of `engine_fingerprint`/`engine_is_stale` directly, `build_multi_board_payload`'s `engine=` embedding, `compute_multi_etag`'s fold, and `_send_static`'s `Cache-Control`) — all red before the change (missing attrs/params), green after. `scripts/cairn/tests/js/engine-stale-banner.test.js` (new, 6 tests, source-text-guard style, pin (e)) — green. Full suites: Python 598/598, JS 321/321.

Heads-up for the merge order: kept the `compute_multi_etag` edit additive-only (new optional params, `None` skips the fold, existing hasher loop untouched) specifically so it shouldn't conflict with PT-50's concurrent `compute_etag`/archive-glob changes — but I haven't seen that diff, so a rebase may still be needed.
