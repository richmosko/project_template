**Gate 1 ruling (architect).** Source census of every z-index in `scripts/cairn/dashboard/src` plus one live browser measurement at `4327ea9`.

**Ladder, as measured — with one correction to the ask.**

| Rung | Value | Where (measured) |
|---|---|---|
| Content | `z-auto` | inside the page root's `isolate` children |
| Sidebar container | `z-10` | `ui/sidebar/sidebar.svelte:84` (`fixed inset-y-0 z-10`) |
| **Sidebar rail** | **`z-20`** | `ui/sidebar/sidebar-rail.svelte:25` — **the ask said rail `z-10`; it is `z-20`.** Two rungs, not one |
| Header | `z-40` | `App.svelte:360` |
| Portal'd floating overlays | `z-50` | `app.css:357` floor `[data-bits-floating-content-wrapper]{z-index:50}` (PT-110), plus each content class: popover, dropdown-menu, select (`relative isolate z-50`), tooltip, sheet-content, sheet-overlay |

Nothing in `src/` declares a z above 50 today, so guard 2 below is satisfiable as written.

**The subtlety the spec must carry, or the ladder is misleading.** Two different things wear `z-50`:
- **Portal'd** overlays escape every `isolate` because they are re-parented to `<body>` — measured live: the ThemeSettings popover's wrapper has `parentElement === BODY`, `z-index: 50`, position `absolute`.
- **In-content** library overlays do **not** escape: LayerChart's `.lc-tooltip-context{,-container}` are forced to `z-50` by `ui/chart/chart-container.svelte:85`, and the two chart tooltips (`TokenCostChart.svelte:551`, `IssueFlowChart.svelte:308`) carry `z-50` in flow. Those are safe **only** because their page-root ancestor carries `isolate` (PT-117). **A `z-50` inside an isolated block is a local 50, not a global one** — that sentence is the point of the whole entry.

**Item (1), the overlay-over-header verification.** Measured by me for the one overlay actually used on the board: with the header pinned at y 0–89 and the popover open at y 62–194, the two overlap by 27 px and **all 21 hit-test points in the overlap strip return the overlay**, never the header. The remaining types are the lead's leg: the sidebar's own Tooltip (collapsed rail) and its mobile Sheet — the Sheet is behind the `md:` breakpoint and is **not measurable at desktop width; record it as unmeasured rather than asserting it**.

**Item (2), spec placement.** A new `### Stacking order (z-tier ladder)` subsection under `## Unified shell (PT-72)` in `docs/DESIGN/design-system-spec.md` — the shell (sidebar + header) is exactly what the ladder governs, and the section already owns the persistent-chrome contract. It carries the table above, the local-vs-global sentence, and the PT-110/PT-117 reasons in one line each. ux-designer writes it.

**Item (3): no dashboard code change.** The rail's `z-20` is a documentation delta, not a defect — it sits between the sidebar container and the header, which is where a resize handle belongs. Nothing to hand the implementation-lead.

**Guards (qa writes; red at gate 2).**
1. **Structural `isolate` scan.** Parse `App.svelte` from the page-root element (`div` with `min-h-screen`, L326) to its matching close; collect element children at depth 1 **including those inside `{#if}` / `{:else}` branches** — today three: the content wrapper (L432), `section[aria-label="Board"]` (L665), `section[aria-label="Issue Tracking"]` (L693). Assert every non-`<header>` child carries `isolate`. **Derive the count; never hard-code three.** The test must also assert the parser found at least one child — a scan that silently finds nothing must fail, not pass.
2. **No rung above 50 without a reason.** Scan every `.svelte` and `.css` under `src/` for Tailwind `z-<n>`, arbitrary `z-[<n>]`, and raw `z-index: <n>`; any value > 50 must sit on a line (or the line above) that names the ladder. Include a control that proves the scan can fail — a synthetic `z-[60]` string checked through the same function.
3. **Rungs pinned to source.** Assert `z-40` on the header, the `[data-bits-floating-content-wrapper]` floor at 50 in `app.css`, sidebar container `z-10`, rail `z-20`. Drift in either direction trips it, and the spec's table stops being a claim about the past.
4. **Spec presence.** The `Stacking order` subsection exists under Unified shell and names all five rungs, so doc and code cannot drift silently.

**Writers.** ux-designer → `docs/DESIGN/design-system-spec.md`. qa → the four scans (`scripts/cairn/tests/`). implementation-lead → nothing; item (3) found no code change, and if that holds there is no `dist/` rebuild in this feature.
